# 项目演进与扩展需求方案 (v2.0 规划)

> 维护者：项目架构师
> 状态：规划中（已提入架构演进路线图）

基于目前项目的实现基础（基于 QTcpSocket 和自定义 PDU 的 Client-Server 架构、自研三级内存池、单线程文件分块上传、MySQL 连接池支持），规划以下系统扩展需求方案大纲。该方案具备高度的可扩展性，能够使当前基础演示项目逐渐向企业级应用演进。

## 1. 核心业务功能扩展 (Business Features)

当前仅支持 1v1 聊天和基础文件增删改传。扩展方向将围绕“群组协作”与“云盘特性”展开。

| 需求编号 | 扩展功能模块 | 功能说明 | 架构/接口影响与实现思路 |
|----------|--------------|----------|-------------------------|
| **EXP-BUS-01** | **群组聊天 (Group Chat)** | 支持创建群、邀请入群、群组广播、群内成员查看。 | 新增 `group_info` 与 `group_member` 数据表；PDU 需新增 `ENUM_MSG_TYPE_GROUPCHAT_*` 系列枚举；服务端 `MsgHandler` 需支持群发消息的遍历分发机制。 |
| **EXP-BUS-02** | **文件秒传 (Fast Upload)** | 利用文件 MD5 哈希校验，如果服务器已存在相同内容文件，直接建立软链接/数据库映射。 | 客户端在发送 `UPLOADFILE_INIT` 前先发 `UPLOADFILE_CHECK_MD5`。若命中，服务器仅增加一条文件的虚拟记录。需建立全局文件 Hash 索引表。 |
| **EXP-BUS-03** | **公共分享外链 (Public Link)** | 生成带提取码的文件下载外链，类似于百度网盘。 | 服务端生成唯一的短码映射（存于 DB），未来可引申出轻量级的 HTTP Server 模块用于提供外链下载页（与当前的 TCP 二进制协议平行）。 |
| **EXP-BUS-04** | **富媒体消息支持 (Rich Media)** | 支持在聊天中发送图片缩略图、表情包或短语音。 | 消息体不能仅依赖 `char msg[]` 文本，PDU 中的数据载荷区需支持携带富媒体资源 ID 甚至直接分块传输二进制图片（结合现有的文件分块收发协议）。 |

## 2. 系统健壮性与网络层演进 (Reliability & Network)

当前网络模型为裸 TCP，缺乏异常状态处理和优雅的反馈机制。

| 需求编号 | 扩展功能模块 | 功能说明 | 架构/接口影响与实现思路 |
|----------|--------------|----------|-------------------------|
| **EXP-NET-01** | **应用层心跳机制 (Heartbeat)** | 解决假死连接问题，自动释放僵尸客户端资源。 | 引入 `PING/PONG` PDU 类型。客户端每 30 秒发送心跳；服务端 `MyTcpSocket` 记录最后活跃时间，配合定时器踢出超时连接（清理 `tcpsocketlist` 和 DB 的 online 状态）。 |
| **EXP-NET-02** | **断线自动重连** | 网络波动后，客户端自动重新建立 TCP 连接并恢复会话状态，无缝收发缓存的消息。 | 客户端需实现重连退避算法（Exponential Backoff）；重连后发送携带 Token/SessionID 的恢复请求，而非重新输入密码登录。 |
| **EXP-NET-03** | **UI 异步进度与队列控制** | 修复目前文件操作（如大文件下载与复制分享）引起的 UI 阻塞，增加传输速率显示。 | 淘汰现有的单线程阻塞读写，全面转向 Qt 的事件循环异步读写（`readyRead`/`bytesWritten`）；引入上传/下载任务调度队列。 |

## 3. 安全防护演进 (Security)

从简单的演示安全机制，转为防窃听、防碰撞的可靠系统。

| 需求编号 | 扩展功能模块 | 功能说明 | 架构/接口影响与实现思路 |
|----------|--------------|----------|-------------------------|
| **EXP-SEC-01** | **传输层加密 (TLS/SSL)** | 防止 PDU 被抓包直接读取账号密码及聊天内容。 | 在现有的 `QTcpSocket` 与 `QTcpServer` 基础上，平滑升级至 `QSslSocket` 与 `QSslServer`。服务端加载自签名证书。 |
| **EXP-SEC-02** | **数据库凭据加密与加盐哈希** | 废弃无盐 MD5 密码存储；剥离硬编码的数据库密码。 | 使用 Bcrypt 或 PBKDF2 对用户密码加盐存储（提升彩虹表破解难度）。配置系统由明文 `connect.config` 转为使用受保护的环境变量或加密的本地配置。 |

## 4. 架构解耦与现代化 (Architecture Evolution)

为支持将来的高并发需求和更好的可维护性准备。

| 需求编号 | 扩展功能模块 | 功能说明 | 架构/接口影响与实现思路 |
|----------|--------------|----------|-------------------------|
| **EXP-ARC-01** | **消息载荷序列化 (Protobuf/JSON)** | 目前的自定义 PDU 扩展字段极度受限于 `caData[64]`。 | 保留 PDU 包头用于粘包拆包，但将柔性数组区域替换为 Google Protobuf 或 JSON 格式序列化流。这将极大增强接口扩展的灵活性，避免无尽的枚举和数据结构扩充。 |
| **EXP-ARC-02** | **逻辑与存储微服务剥离** | 将文件存储 IO 与高频的聊天路由分离。 | 目前服务端既处理数据库，又读写本地磁盘（还会受限于内存池分配大对象）。架构上可将"文件服务器"剥离为独立进程，客户端鉴权后直接通过 Token 与文件服务器建立连接上传/下载。 |
| **EXP-ARC-03** | **缓存层引入 (Redis)** | 减轻高频查询对 MySQL（及连接池）的压力。 | 用户的在线状态（`online`）、心跳更新、以及 `friend` 关系的快速校验，从 MySQL 迁移到 Redis，提升 QPS 并解决并发锁争用风险。 |

---

### 实施路径 (Roadmap)

本版本优先进入第一阶段，实现基础网络健壮性与外链分享框架：
1. **EXP-NET-01**: 实现应用层心跳（PING/PONG）机制。
2. **EXP-BUS-03**: 实现文件分享外链数据库结构及协议框架定义。
