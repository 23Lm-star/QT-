# 全量业务功能审计复审报告（2026-11-14）

## 结论

当前工作区存在多个可达业务缺陷和协议健壮性缺陷。已确认 2 个网页端功能错误、3 个服务端/客户端边界缺陷和 1 个验证码安全缺陷。协议冒烟通过不能覆盖这些问题。

本轮只做审计，不修改业务代码。工作区原有未提交修改全部保留。

## 审计范围与方法

- 账号注册、登录、验证码、会话。
- 好友、私聊、群、目录、上传下载、分享、网页网关和协议解析。
- 使用 CodeGraph 同步当前工作区，追踪请求入口、响应分发、数据库/文件状态和跨端字段语义。
- 对服务端处理器、桌面客户端收包、网页请求路由进行边界与异常分支检查。
- 对关键网页逻辑执行运行时 mock 复现。
- 执行 `node web/tests/protocol_smoke.mjs` 验证协议层回归边界。

## 已确认问题

### P1-001 网页注册成功被判定为失败

- 位置：`web/frontend/src/protocol/commands/account.js:79-83`
- 证据：服务端注册成功使用标准码 `0`（`Server/msghandler.cpp:338`），网页端却只有在 `ret !== 0` 且不等于少数负值时设置 `success=true`。
- 复现：用返回 `caData[0..3]=0` 的响应调用 `account.register()`，实际结果为 `{"ret":0,"success":false}`。
- 影响：网页用户注册成功后界面显示失败或错误提示，调用方不会按成功路径刷新状态。
- 修复方向：注册成功判定必须使用 `ret === 0`，失败分支按具体负码显示。
- 回归测试：增加标准码 0、账号已存在、验证码错误、数据库不可用四组断言。

### P1-002 网页同响应类型并发请求互相覆盖

- 位置：`web/frontend/src/protocol/client.js:88-90,117`
- 证据：`pending` 使用 `respType` 单值作为键。第二个相同响应类型请求会覆盖第一个等待者，返回包只能唤醒后一个请求。
- 复现：对同一 `NetClient` 并发发出两个 `request(23,24,...)`，注入一个 24 响应，结果为 `['p1:请求超时 (type=23)','p2:resolved']`。
- 影响：重复刷新目录、并发列表请求或相同响应类型的快速操作会出现请求超时、响应错配和界面状态回退。
- 修复方向：为请求增加 request id 或按响应类型维护 FIFO 队列。超时和断线时只收敛对应请求。
- 回归测试：同响应类型并发、一个请求超时后第二个仍成功、断线同时拒绝全部请求。

### P1-003 目录分页 offset 越界导致服务端越界访问

- 位置：`Server/msghandler.cpp:853-867`
- 证据：先执行 `qMin(limit, total-offset)`，再执行 `if(offset>total) offset=total`。当 `offset > total` 时无符号减法下溢，`count` 仍可为 limit，后续访问 `rows[int(offset+i)]` 超出 QVector 范围。
- 触发：客户端翻页期间目录条目减少，或认证用户直接构造超过总数的 23 请求。
- 影响：服务端可能读取越界内存、返回错误条目或进程异常。属于可达的远程输入问题。
- 修复方向：先将 offset 钳制到 total，再计算 count。增加 offset 大于 total 的服务端测试。

### P1-004 文件分享接收人数未校验导致超大分配和越界读

- 位置：`Server/msghandler.cpp:1012-1018`
- 证据：`revUserCnt` 直接从客户端 `caData` 读取，没有验证非负、没有验证 `revUserCnt * 32 <= pdu->uiMsgLen`，随后参与 `mkPDU(pdu->uiMsgLen-revUserCnt*32)` 和源缓冲区偏移复制。
- 触发：已认证客户端发送负数或大于消息可承载人数的接收人数。
- 影响：整数转换/下溢可触发超大内存申请，拷贝源地址越界，可能终止服务端进程。
- 修复方向：先验证 `0 < revUserCnt`、乘法不溢出、接收人区域和路径区域都在 `uiMsgLen` 内，再分配和复制。

### P1-005 服务端多个路径请求把 caMsg 当作无限 NUL 字符串

- 位置：`Server/msghandler.cpp:674,709,810,1257,1305` 等。
- 证据：`QString::fromUtf8(pdu->caMsg)` 和同类调用没有使用 `pdu->uiMsgLen`。协议接收层只保证整帧长度，不保证 caMsg 内存在 NUL。
- 触发：已认证客户端发送 `uiMsgLen=0` 或不含 NUL 的合法长度 PDU。
- 影响：服务端会继续读取当前 PDU 之外的缓冲区内容，造成路径错读、越界读和异常文件操作。多个目录、删除、改名和移动入口受影响。
- 修复方向：统一使用按长度的 UTF-8 解码，并对路径请求强制检查 NUL 位置和最大长度。

### P1-006 客户端收包未拒绝非法总长度，uiTotalLen=0 会卡死处理循环

- 位置：`Client/client.cpp:513-520`
- 证据：只判断缓存长度是否大于等于 `uiTotalLen`，没有检查 `uiTotalLen >= sizeof(PDU)`、`uiMsgLen == uiTotalLen-sizeof(PDU)` 或最大长度。`uiTotalLen=0` 时 `remove(0,0)` 不推进缓冲区，循环永久执行。
- 触发：服务端、代理或损坏链路发送 0 长度或小于 76 字节的伪 PDU。
- 影响：桌面客户端 GUI 线程卡死，无法继续操作。
- 修复方向：在读取头部后先做完整长度、消息长度和上限校验，非法帧清空/断开并退出循环。

### P1-007 验证码使用可预测随机数

- 位置：`Server/msghandler.cpp:61-74`
- 证据：进程只用 `QTime::currentTime().msec()` 作为 `qrand()` 种子，种子空间只有 1000 种，验证码序列可通过观测时间和少量响应预测。
- 影响：验证码不能提供有效的自动化防护，攻击者可降低注册、登录和接口探测成本。
- 修复方向：使用操作系统 CSPRNG（密码学安全随机数）生成验证码和图像噪声，避免 `qrand/qsrand`。
