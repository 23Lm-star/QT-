# REQ-MIG-001｜迁移状态归一

## 目标与当前进展

消灭三类存量数据迁移态，使代码中不再保留"迁移前/迁移后"双分支：

1. **密码空盐**（源自 REQ-AUTH-002）：`salt=''` 老账号按裸 MD5 比对，登录时自动补盐；目标=批量补盐后删除全部空盐分支。
2. **文件存量迁移**（源自 REQ-EXT-FILE-001 T6）：旧物理文件 copyOnly 进 `filesys/objects/` 内容寻址对象，`msghandler.cpp` 保留 8+ 处物理回退分支；目标=覆盖率 100% 后删回退分支、删旧文件树、移除启动迁移调用。
3. **逻辑键归一化**（源自 REQ-EXT-FILE-002 收紧）：启动时 `normalizeLogicKeys()` 每次跑存量键转换；目标=确认无残留后删除。

**范围外**：老客户端协议兼容分支（TRANSFER_ID_LEGACY、无附加区空 ID、分享状态字回带）——协议版本设计，非数据迁移态。

- 用户追加确认（2026-11-12）：文件域数据代际漂移按“清空文件域表 + 清空 filesys 树 + 建干净基线”处置；`Server/filesys/wcy` 下两个旧文件直接删除，不备份。

- DB 连接参数从 `Server/connect.config` 运行时读取，不在脚本/文档中写库密码。
- 关键技术事实（实施依据）：
  - 盐公式：`pwd = md5(客户端MD5 + salt)` hex；老数据 `pwd` 即客户端 MD5 原值 ⇒ 可离线批量升级 `pwd=md5(pwd+新盐)`。
  - 迁移映射 `file_migration_map.status`：`mapped` / `skipped_name_conflict` / `failed`；old_path 键形态 `<filesys>/<user>/...`。
  - 逻辑键 canonical 判定：`fileobjectstore.cpp:67 isLogicKeyForm` + `normalizeParent`；归一范围=user_file、upload_session、file_migration_map（group_file 无 parent_path）。
  - 磁盘布局：`filesys/objects/<sha前2位>/<object_id>` 对象、`filesys/.staging/` 暂存、旧文件在 `filesys/<user>/...`。
  - 盘点结论：空盐账号 0、非 canonical 键 0、非 mapped 映射 1 条（skipped_name_conflict 属预期策略）；现行 file_object 72 行对象在盘上全部缺失，盘上 97 个对象属旧代际，89 个 active 条目引用的对象无一存在 ⇒ 文件域重置为唯一归一路径。
- 收敛边界（重要）：目录仍保留“物理 mkdir + 条目”双写（`MKDIR` 语义），因此 deldir/flushfile/rename/move 中**目录**的物理分支保留；被删除的是**文件**的旧物理路径回退（新架构文件只存 objects/）。
