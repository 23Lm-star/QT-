### 实施落点

- 协议（两端 `protocol.h` 只追加，逐字一致已 diff 核对）：LIST_TOTAL_CAP=1000；7 请求关键词槽 caData[8,40)、8 响应 capped@16；11 请求 limit@0/offset@4、12 响应 total@12/has_more@16/capped@17（ret@0/truncated@4 恒 0/count@8 保留）。**载荷零变更、编号零新增**。
- 服务端：`handleAllUsers` 加关键词（LIKE ESCAPE '!' 预编译绑定）与 CAP 钳制（COUNT→封顶→offset≥total 空页→effLimit=min(limit,remain)）；`handleFlushFriend` 改 UNION 子查询 COUNT＋ORDER BY n ASC＋LIMIT/OFFSET＋CAP；`onlineuser()`/`flushfriend()` 读写新字段。
- 桌面：OnlineUser 搜索框（回车/按钮、≤31 字节拦截、翻页携带关键词、封顶/无匹配提示）；Friend 页「加载更多好友」、编号跨页连续、刷新/删友/加友成功重置第 0 页、封顶首页弹窗；**在途拦截守卫**（审计新增，见下）。
- 网页：friend.js 新增 002 布局纯函数（build/parse）与分页 fetch；弹窗真分页＋搜索＋封顶注记；friends store 数据层全量（limit=0≤上限，封顶提示）＋onlineUsers 分页累积（按名去重防漂移）；FriendPanel 展示层切片＋加载更多。

### 实施中的重要修正与随带修复（偏离/超出原计划处）

1. **网页注册成功判定既有缺陷（随带修复）**：`account.js register()` 仍按旧语义「ret≠0 即成功」，与 PROTO-CODE-001 标准码（0=成功）相反——网页注册对标准码服务端自 2026-11-13 起必失败。002 网页回归（M2 e2e）暴露，按已确认标准码契约最小修复（`success = ret===LoginRet.SUCCESS`）。非 002 引入。
2. **网页 e2e 基线陈旧对齐（测试基建，非削弱断言）**：chat_e2e/share_e2e 多处断言停在旧契约——登录/同意 push 期望 ret=1（标准码 0）、在线列表用字符串 includes 条目数组（001 起返回 {name,online}）、外链 L18/L21 期望「目录可建链接/逃逸取回才拒」（AUDIT-001 起创建阶段即拒）、L12 期望过期复用 ok=true/state=1（PROTO-CODE-001 R4 起标准码表达 ok=false/state=-2017）。逐条对齐到**已确认的现行规则**后全过。
3. **e2e 挂死与强退崩溃（测试基建）**：异常路径未关闭已登录会话 → 30s 心跳定时器使 Node 进程永不退出、编排无限等待；改 try/finally 覆盖注册/登录保证会话关闭。曾试 process.exit 强退，Node 26 下 WS 关闭 handle 未落定触发 libuv 断言崩溃（0xC0000409），已回退为自然退出。
4. **在途拦截守卫（审计新增）**：连续快速搜索会使两个在途响应交错追加混页、双击加载更多会重复请求同一页。OnlineUser 搜索/加载更多与 Friend 加载更多加 m_inFlight 拦截（响应到达清除）；resetAndRequest/flushfriend 为强制重置入口不设拦（断线后重开窗口/点刷新即恢复）。刷新与在途加载更多的交错属 001 已接受的弱一致性同类，不另加生成号追踪。
5. **README 补注**：网页 e2e 编排脚本（run_m*_e2e.py）同样需要 `CLOUDDISK_CAPTCHA_TEXT_FOR_TESTS=1`（此前只注明直连套件，M2 首跑因此失败）。
