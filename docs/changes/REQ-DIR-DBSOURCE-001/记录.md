# REQ-DIR-DBSOURCE-001｜目录数据唯一权威为数据库条目树

## 目标与当前进展

用户裁决（2026-11-22）：以后客户端获取目录的唯一权威和数据来源是数据库条目树，物理目录仅用于路径校验。**已完成并验证（2026-11-22，分支 `codex/req-dir-dbsource-001`）。**

## 计划与重要决定

- **受影响面**（全仓扫描 `entryInfoList`）：`flushfile`（23/24 主列表）与 `listdir`（58/59 移动目标目录）两处把物理目录当数据源；`reclaimscheduler` 的 *.part 扫描属基础设施不涉及；`changedir`/沙箱校验的物理存在性属「路径校验」用途按裁决保留；目录物理双写（mkdir 建、deldir 同步清，REQ-DIRDEL-GHOST-001）保留为磁盘卫生。
- **改动**：flushfile 移除物理并入与墓碑过滤（纯 `listEntries`）；listdir 数据源改 `listEntries(parentKey)` 仅取 is_dir=1，名字序沿用物理 QDir 的不区分大小写序，截断口径不变；`FileObjectStore::deletedDisplayNames` 随两处消费移除成为死代码，一并删除（validatePath 先例）。
- **响应布局零变更**：23/24、58/59 载荷与分页字段不动，仅数据来源收口；两端 protocol.h 不动。

## 验证

| 验收项 | 用例 | 实际结果 |
|---|---|---|
| 来源一（孤儿壳不可见） | 探针：MKDIR ghostdir + 外部伪造无条目物理壳 orphanshell → flushfile/listdir | flushfile 仅含条目 ghostdir；listdir=['ghostdir']；孤儿壳不入列（修复前物理并入会显示） |
| 来源二（删除链） | 探针：DELDIR → flushfile + 物理壳 | 条目消失即清单消失，物理壳同步清理（REQ-DIRDEL-GHOST-001 口径） |
| 回归一 | `entry_ops_e2e.py`（flushfile/listdir/目录增删改） | **38/38** |
| 回归二 | `REQ-EXT-SEC-002/verify.py`（逻辑路径与授权，V1 即「只列条目不含无条目物理文件」口径） | **14/14**（顺带完成登录 shim cid 化+标准码+upload tid/轮询适配，sec2a 密码链重置） |
| 编译 | Qt/MinGW Release 重编译 | 通过（零错误） |

调试插曲（如实记录）：探针曾误报 listdir 无响应，根因是探针自身读 59 响应 count 用了 flushfile 的偏移 [12:16]（listdir 的 LIST_TRUNC_RESP_COUNT_OFFSET 在 [8:12]），服务端行为正确。

## 审计与最终结论

规则落地：目录数据唯一权威=数据库条目树；物理目录仅路径校验（changedir/沙箱）与磁盘卫生（双写+同步清）。无条目物理残留从此不可见（孤儿壳成为纯磁盘现象，可随时手删或留待同名重建复用）。SEC-002/entry_ops 顺带完成时代适配，剩余未适配直连套件按 TODO 残留推进。
