# REQ-REDIS-001｜Redis 最小引入面 ①②计划执行

## 执行目标

在 `CLOUDDISK_REDIS_URL` 可选门控下，为服务端接入 Redis 的验证码状态和在线状态存储。默认未配置 Redis 时保持现有行为，Redis 运行中失败时按请求回退并记录日志。

## 实施边界

- 修改范围限于服务端 Redis 适配、验证码状态、在线态处理、44 请求可选 `clientId` 槽及构建依赖。
- 不新增协议编号，不改变响应布局，不新增数据库迁移。
- 不实施秒传存在性缓存、限流缓存、多实例共享数据库或客户端独立 Redis 逻辑。
- 不修改用户级配置，不提交、推送、合并或发布。

## 分阶段计划

### 阶段一：基线与依赖确认

1. 使用 CodeGraph 定位验证码、登录、PING、断开、7/8 查询和 44 请求的调用链。
2. 核对 `Server.pro` 的构建方式、Qt/MinGW 位数和 hiredis 的获取及链接形态。
3. 保存 Redis 门控关闭时的服务端构建基线和相关协议探针结果。
4. 确认测试使用隔离 Redis 实例，避免与其他服务或测试共享键空间。

通过条件：影响范围可定位，依赖可编译，基线结果已记录；不满足时停止进入实现阶段。

### 阶段二：Redis 适配与门控回退

1. 新增服务端内部 Redis 适配层，统一连接、短超时、命令结果校验和日志处理。
2. 从 `CLOUDDISK_REDIS_URL` 读取连接信息，未配置时不建立 Redis 连接。
3. 为连接失败、超时、错误回复和脚本失败提供请求级回退接口。
4. 将 hiredis 接入 `Server.pro`，保持 Qt 5.14.2/MinGW 7.3 的 Release 构建可用。

通过条件：门控关闭不触发 Redis 依赖路径，门控开启可连接测试实例，故障能回退且服务端不退出。

### 阶段三：验证码状态接入

1. 为 44/3 请求解析可选 `clientId`，缺省时使用 `connId`。
2. 接入 `cap:{id}:code`、`cool`、`fail`、`lock` 键。
3. 使用 TTL（生存时间）替代手工过期判断，失败计数和锁定按 `clientId` 维度处理。
4. Redis 失败时回退原连接内存状态，并记录带请求上下文的日志。

通过条件：同一 `clientId` 重连不重置冷却和锁定，旧客户端无槽时仍可完成原流程。

### 阶段四：在线态接入

1. 登录成功和每次 PING 使用 `SETEX online:{user} 90 {loginVersion}`。
2. 断开使用 Lua CAS（比较并交换）脚本，仅在版本匹配时删除在线键。
3. 7/8 查询在 Redis 开启时按页读取在线键，保留 `user_info.online` 双写。
4. 保留启动期对账和 Redis 不可用时的数据库回退。

通过条件：正常断开、旧连接误删、新连接登录、进程异常退出和 TTL 自愈场景均符合设计。

### 阶段五：验证与审计

1. 运行协议兼容探针，确认 44 可选槽、旧客户端回退和响应布局。
2. 运行验证码专项探针，覆盖重连冷却、失败锁定、TTL 恢复和 Redis 故障回退。
3. 运行在线态专项探针，覆盖心跳续期、踢线 CAS、进程终止后的 TTL 自愈和 7/8 分页。
4. 执行 Redis 开启与关闭两组服务端构建及相关回归。测试共享 TCP 5000 和 MySQL，必须串行运行。
5. 检查第二连接在 Redis 命令执行期间的心跳或请求延迟，确认同步命令没有造成不可接受的事件循环阻塞。
6. 对实现和测试进行一次独立审计，区分确认缺陷、待验证疑点、非阻塞建议和未验证项。

## 验收矩阵

| 验收项 | 验证方式 | 通过标准 |
|---|---|---|
| 默认关闭零回归 | 未设置 `CLOUDDISK_REDIS_URL`，运行相关协议与服务端回归 | 行为与基线一致 |
| 验证码跨重连 | 同一 `clientId` 多连接请求 44/3 | 冷却、失败计数和锁定不被重置 |
| 旧端兼容 | 44 不携带 `clientId` | 按 `connId` 完成原流程 |
| 在线续期 | 登录、连续 PING、查询 7/8 | Redis TTL 按预期续期，在线状态正确 |
| CAS 防误删 | 新旧连接交错登录、断开 | 旧连接不能删除新连接在线键 |
| 异常自愈 | 杀掉服务端进程，等待 TTL | 在线键自动过期，启动对账仍可执行 |
| 故障回退 | 停止 Redis、制造超时或脚本错误 | 当前请求回退、记录日志、服务端存活 |
| 事件循环影响 | Redis 命令期间第二连接发心跳或请求 | 延迟在预先约定阈值内，无连接异常断开 |
| 构建兼容 | Qt 5.14.2 MinGW Release 构建 | Server 构建成功，依赖链接正确 |

## 回退与恢复

- 运行回退：删除或清空 `CLOUDDISK_REDIS_URL`，服务端恢复现有内存验证码和数据库在线态路径。
- 数据回退：不涉及数据库迁移，停止 Redis 不会要求数据回滚。
- 代码回退：保留门控关闭路径，若专项验证失败，撤销 Redis 适配调用点即可恢复原行为。
- 测试恢复：专项测试使用独立键前缀或隔离 Redis 实例，测试结束清理自身创建的键，不清理无关 Redis 数据。
