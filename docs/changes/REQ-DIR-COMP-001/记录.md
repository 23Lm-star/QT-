# REQ-DIR-COMP-001｜目录操作失败补偿队列需求分析

## 目标与当前进展

为现有周期性回收调度器增加目录操作补偿能力：目录相关磁盘操作失败时，将可重试的补偿任务持久化到数据库；调度器按固定周期读取并处理任务。处理达到目标最终状态后删除任务；处理失败则保留任务并更新重试元数据，等待下一周期重试。

本文件为需求分析和边界确认，当前未实施代码、数据库迁移或测试。

## 已确认的业务规则

| 项目 | 已确认规则 |
|---|---|
| 队列存储 | 新增数据库表，跨服务端重启保留 |
| 任务内容 | 操作类型、账号、源路径、目标路径、重试次数、下次重试时间、最后错误等元数据 |
| 重试 | 固定周期重试；失败任务继续保留，不设置自动放弃上限 |
| 幂等 | 以最终状态为准。目标状态已满足时视为成功并删除任务 |
| 入队范围 | 所有目录相关磁盘操作失败都应入队，包括用户请求和内部目录操作 |
| 并发 | 允许多实例并行处理；必须通过数据库抢占/租约避免同一任务被重复执行 |

## 当前实现背景

当前 `Server/ReclaimScheduler` 已在主线程 `QTimer`（定时器）上按有界批次处理 `.staging` 文件和 `file_object` 物理对象回收。目录操作则分散在注销、删除目录、创建目录、重命名、移动及相关内部流程中，磁盘操作与数据库操作存在跨资源失败边界。

本需求应复用现有调度周期和限速思路，新增独立的目录补偿处理线，不改变既有对象回收语义。

## 补偿任务模型

建议新增数据库表 `directory_operation_compensation`（名称可在设计阶段调整），至少包含：

- `task_id`：任务主键。
- `operation_type`：操作类型，例如 `create_storage_root`（创建存储根目录）、`create_user_root`（创建用户根目录）、`create_directory`（创建目录）、`delete_directory`（删除目录）、`rename_directory`（重命名目录）、`move_directory`（移动目录）、`delete_user_root`（删除用户根目录）、`quarantine_user_root`（隔离用户根目录）、`ensure_directory_parent`（确保父目录存在）、`commit_staged_file`（暂存文件转正）、`rollback_staged_file`（回退暂存文件）、`cleanup_orphan_directory`（清理孤儿目录）等。操作编号必须稳定，不复用已有协议编号。
- `account`：服务端确认的账号身份，不信任客户端自由传入的账号字段。
- `source_path`：源目录路径；创建操作可为空。
- `target_path`：目标目录路径；删除操作可为空。
- `retry_count`：已尝试次数。
- `next_retry_at`：下次允许执行时间。
- `last_error`：最近一次失败摘要，不写入密码、密钥等敏感信息。
- `status`：至少区分待处理和已被实例抢占的状态。
- `claim_owner`、`claim_until`：多实例并行时的租约信息。
- `created_at`、`updated_at`：审计和排序时间。

路径必须保存为服务端规范化后的相对用户根路径，禁止把未经校验的绝对路径直接写入队列。

## 处理流程

1. 目录操作执行磁盘步骤。
2. 磁盘步骤失败时，按操作类型、账号和规范化路径写入补偿任务；入队失败必须记录错误并保留原操作失败结果。
3. 调度器按 `next_retry_at`、创建时间和有界批次读取任务。
4. 实例通过条件更新抢占任务，设置租约和处理状态；租约过期的任务可被其他实例重新抢占。
5. 执行前重新校验账号归属、用户根边界、源/目标路径和操作前置条件。
6. 先检查最终状态：
   - 删除目标已不存在，视为成功；
   - 创建目标已存在且符合当前账号及目录约束，视为成功；
   - 移动后源已不存在且目标位置已满足预期，视为成功；
   - 删除用户目录已完成，视为成功。
7. 最终状态未满足时执行对应目录操作。
8. 成功后删除任务；失败后增加重试次数、写入错误和下一次固定重试时间，释放租约并恢复待处理状态。

## 操作类型边界

目录补偿类型按“实际目录或目录路径发生的磁盘操作”完整覆盖以下类别。任务的 `operation_type`（操作类型）必须使用稳定枚举值，不能把不同语义的操作合并成一个“目录失败”类型。

### 用户目录生命周期

| 类型 | 典型入口 | 成功判定重点 |
|---|---|---|
| `create_storage_root`（创建存储根目录） | 服务端初始化或注册前创建 `filesPath` | 存储根目录存在且位于配置根路径 |
| `create_user_root`（创建用户根目录） | 注册、登录时补齐缺失用户目录 | `filesPath/<account>` 存在且归属当前账号 |
| `delete_user_root`（删除用户根目录） | 注销账号、账号资产清理 | 用户根目录及允许的子树已删除 |
| `quarantine_user_root`（隔离用户根目录） | 用户目录删除失败后的移入 `.deleted` | 原路径不存在，隔离目标存在且仍在服务端隔离根内 |
| `create_quarantine_root`（创建隔离根目录） | 首次使用 `.deleted` 隔离目录 | 隔离根存在且未越出 `filesPath` |

### 用户可见目录操作

| 类型 | 典型入口 | 成功判定重点 |
|---|---|---|
| `create_directory`（创建目录） | 新建文件夹请求 | 目标目录存在，逻辑目录条目与物理目录状态一致 |
| `delete_directory`（删除目录） | 删除目录请求、物理残留清理 | 目标目录不存在，逻辑条目按现有软删规则处置 |
| `rename_directory`（重命名目录） | 文件或目录重命名请求 | 源路径不存在，目标路径存在，后代逻辑路径已级联 |
| `move_directory`（移动目录） | 移动文件请求中的目录分支 | 源路径不存在，目标位置存在，后代路径和逻辑条目一致 |
| `ensure_directory_parent`（确保父目录存在） | 创建目录、上传转正、分享接收等操作的父目录准备 | 所需父目录链存在且全部位于授权根内 |

### 文件操作中涉及的目录实体或路径

| 类型 | 典型入口 | 成功判定重点 |
|---|---|---|
| `move_file`（移动文件） | 任意目录间移动文件 | 源文件不存在，目标文件存在且逻辑条目已完成位置更新 |
| `rename_file`（重命名文件） | 文件重命名请求 | 源文件不存在，目标文件存在，逻辑名称一致 |
| `receive_shared_file`（接收分享文件） | 分享文件转入接收者目录 | 接收目录存在，目标条目已登记，物理对象引用一致 |
| `commit_staged_file`（暂存文件转正） | 上传完成后从 `.staging` 转入对象目录 | 目标对象已落定，暂存源按规则删除或保留 |
| `rollback_staged_file`（回退暂存文件） | 转正或登记失败后的清理 | 半成品已删除或安全回到暂存路径，不能丢失仍需续传的源 |
| `create_staging_directory`（创建暂存目录） | 上传初始化、服务启动 | `.staging` 存在且可写 |
| `delete_staging_file`（删除暂存文件） | 上传失败清理、周期回收 | 文件已删除，正在使用的文件不得处理 |
| `delete_object_file`（删除对象文件） | 引用归零后的周期回收 | 对象文件已删除，数据库对象记录按回收规则收敛 |
| `create_object_directory`（创建对象目录） | 对象落盘前建立对象目录链 | 目标目录存在且只在 `objects` 子树内 |

### 存量迁移与内部修复

| 类型 | 典型入口 | 成功判定重点 |
|---|---|---|
| `migrate_legacy_path`（迁移旧路径） | 存量文件或旧目录迁移 | 源与目标达到迁移规则，不能误删迁移源 |
| `repair_directory_entries`（修复目录条目） | 物理目录改名、移动、删除后的逻辑级联 | 数据库条目与物理目录最终状态一致 |
| `cleanup_orphan_directory`（清理孤儿目录） | 无逻辑条目的物理残留目录回收 | 目录确认无有效条目和活动操作后删除 |
| `cleanup_quarantine_entry`（清理隔离项） | 隔离目录后续清理 | 隔离项已安全删除或再次隔离 |

目录列表、切换目录、目录选择器和路径校验属于只读或校验操作。它们自身失败不创建磁盘补偿任务，但若其内部触发了实际创建、移动、重命名或删除步骤，则按对应类型入队。日志目录轮转、测试临时目录等不属于用户资产补偿时，应使用独立的内部清理策略，不能把日志或测试路径写入用户目录补偿队列。

各类型必须记录足以重建目标状态的参数。除账号、源路径、目标路径外，目录级联和同名冲突场景还应保存条目标识、原名称、最终名称或操作版本，防止重试时误作用于后来创建的同名目录。
## 并发与安全要求

- 多实例并行必须使用数据库条件抢占或租约，保证同一任务同一时刻只有一个执行者。
- 执行前和执行后都要做路径规范化及用户根边界校验，拒绝空路径、绝对路径、`..` 越界、符号链接越界和跨账号路径。
- 任务执行不能绕过现有数据库授权、目录命名和自身子树限制。
- 目录操作与补偿执行可能并发；发现目标状态已被其他操作改变时，应重新读取状态并按幂等规则判断，不使用过期快照覆盖新状态。
- 租约、状态更新和任务删除失败必须保留任务，避免“执行失败且任务丢失”。
- 固定周期永久重试可能造成长期积压，需要日志和指标暴露积压量、最老任务年龄、每轮成功数和失败数。

## 验收场景

1. 删除目录磁盘操作失败，数据库新增删除补偿任务；下一周期重试成功后任务消失。
2. 移动目录中途失败，任务保存源/目标路径；重试前目标已达最终状态时直接删除任务。
3. 创建目录数据库登记失败但物理目录存在，补偿任务重试后最终状态一致；不能误删并发创建的目录。
4. 注销删除用户目录失败，任务跨服务端重启仍存在并继续处理。
5. 同一任务被两个服务端实例同时扫描，只有一个实例获得租约并执行。
6. 补偿执行遇到路径越界、账号不匹配或目标状态不安全，任务保留并记录明确错误，不执行磁盘操作。
7. 队列表写入失败时，原目录操作返回失败且日志包含可定位错误；不得伪报成功。
8. 队列达到单轮上限时，剩余任务留到下一轮；调度器不阻塞正常网络处理。

## 影响、风险与验证方式

- **数据影响**：新增一张持久化队列表及索引；不改变既有文件对象回收表语义。需要新增 schema 版本迁移和回滚说明。
- **接口影响**：预计不新增客户端协议号；补偿由服务端内部调度器处理。若需要人工查询或管理任务，需另行立项接口。
- **运行影响**：调度器增加数据库查询、租约更新和目录 IO；必须维持每拍/每轮有界预算。
- **主要风险**：多实例租约失效、同名目录误判、部分级联成功、永久失败任务积压、队列写入与原操作之间无法形成跨资源原子事务。
- **验证**：数据库迁移检查、单任务幂等测试、多实例抢占测试、目录边界测试、注入磁盘权限/占用失败、服务端重启恢复测试、调度器限速和现有回收回归测试。GUI 和真实生产数据库验证需单独标注实际执行结果。

## 待设计事项

1. 数据库表名、字段类型、索引和 schema 版本号。
2. 固定重试周期的配置来源及默认值。
3. 租约时长、续租方式和实例标识生成规则。
4. 各操作类型的精确最终状态判定，以及如何防止同名目录误判。
5. 入队失败时是否需要同步告警、指标或单独的本地持久化兜底。
6. 删除用户目录任务与账号注销状态、登录状态及并发上传的协调规则。

## 审计与最终结论

需求边界已根据用户确认完成：采用持久化数据库队列、固定周期永久重试、最终状态幂等、多实例并行抢占，覆盖所有目录相关磁盘操作失败。当前仅完成需求分析，未开始实现；实施前应先完成数据库模型、租约机制和各操作类型最终状态判定的设计确认。



# 实施计划

## 计划目标

在不新增客户端协议的前提下，为服务端现有周期回收调度器增加目录操作补偿线。所有目录相关磁盘操作失败后持久化补偿任务，调度器按固定周期、有界批次和数据库租约执行。最终状态满足目标时删除任务，其他失败保留并安排下一次重试。

## 影响范围

- 数据库：新增目录补偿任务表、状态字段、租约字段和查询索引，增加 schema（数据库结构）版本迁移。
- 服务端：扩展 `ReclaimScheduler`，新增目录补偿队列访问和处理逻辑。
- 文件域：在目录创建、删除、重命名、移动、用户目录生命周期、暂存转正与回退、对象目录准备及内部修复入口接入失败入队。
- 协议：不增加协议编号，不改变现有请求和响应格式。
- 配置：增加补偿任务批次、固定重试周期和租约时长配置，沿用现有 `reclaim.cfg` 配置加载约定，并保持非法值回退保守默认。

## 依赖与实施顺序

### 1. 建立现状基线和失败入口清单

**目标**：确认所有实际目录磁盘操作和失败分支，避免遗漏入队入口或把只读校验错误写入队列。

**相关位置**：`Server/msghandler.cpp`、`Server/fileobjectstore.cpp`、`Server/reclaimscheduler.cpp`、`Server/operatedb.cpp`、现有 schema 迁移入口。

**工作内容**：

- 以 CodeGraph 查询目录操作函数及调用链。
- 对照需求文档中的操作类型，记录每个磁盘调用的源路径、目标路径、账号来源和失败后的数据库状态。
- 区分用户资产目录、对象存储目录、暂存目录、隔离目录、迁移目录和日志目录。
- 为每个入口确定可重建任务所需的参数，补足条目标识、原名称、最终名称或操作版本。

**通过条件**：形成一份入口到 `operation_type` 的映射，所有会改变目录实体或目录路径的失败分支都有明确接入点。

### 2. 设计并迁移补偿任务表

**目标**：让任务跨进程重启保存，并支持多实例抢占、租约过期恢复和固定周期重试。

**数据约定**：

- `task_id` 主键。
- `operation_type`、`account`、`source_path`、`target_path`。
- `entry_id`、`source_name`、`target_name` 或等价版本字段，按操作类型允许为空。
- `status` 至少包含 `pending`（待处理）和 `claimed`（已抢占）。
- `retry_count`、`next_retry_at`、`last_error`。
- `claim_owner`、`claim_until`、`created_at`、`updated_at`。
- 索引覆盖 `status`、`next_retry_at`、`claim_until` 和创建时间排序。

**工作内容**：

- 遵循现有 schema 版本检查和迁移风格新增表。
- 为字段设置长度、非空、默认值和路径约束，避免空账号或无操作类型任务进入队列。
- 设计重复任务去重键，至少保证同一账号、同一操作类型、同一目标上下文不会无限生成重复任务，同时保留不同版本的有效操作。
- 提供迁移失败时的 fail-fast 行为和必要回滚步骤。

**通过条件**：新库和存量库均能完成迁移，服务端 schema 检查通过，迁移失败不会启动半初始化调度器。

### 3. 实现队列写入接口

**目标**：提供统一的失败入队入口，所有目录操作复用同一套校验和持久化逻辑。

**建议接口**：在 `OperateDB` 或独立的目录补偿存储类中提供创建、抢占、成功删除、失败重排、租约释放和过期租约恢复方法。具体类名按现有代码结构确定。

**工作内容**：

- 只接受服务端规范化后的账号和相对路径。
- 在入队前校验操作类型、账号非空、源/目标路径边界和必要字段组合。
- 通过唯一键或条件更新实现重复入队幂等。
- 入队失败返回明确错误，原目录操作继续按失败语义返回，不能伪造成功。
- 不把密码、令牌或完整异常堆栈写入 `last_error`。

**通过条件**：每种操作类型可插入合法任务，非法路径和缺字段被拒绝，重复失败不会无界复制同一任务。

### 4. 实现多实例抢占和租约

**目标**：允许多个服务端实例并行扫描，但同一任务同一时刻只由一个实例执行。

**工作内容**：

- 生成实例级 `claim_owner`。
- 使用条件更新抢占 `pending` 任务和租约已过期的 `claimed` 任务。
- 租约覆盖一次目录操作的最大预期时间，处理完成前提供必要续租或缩小单拍预算。
- 成功删除和失败重排都带 `task_id + claim_owner` 条件，防止旧实例覆盖新实例结果。
- 服务端异常退出后，其他实例可在租约到期后重新处理。

**通过条件**：双实例并发测试中同一任务不会同时执行，实例崩溃后任务可恢复，旧租约不能删除新实例已更新的任务。

### 5. 扩展周期调度器

**目标**：复用 `ReclaimScheduler` 的心跳和有界预算，增加独立目录补偿处理线。

**工作内容**：

- 增加目录补偿配置、统计字段和轮次失败集合。
- 每拍按 `perTick` 限制处理量，每轮按 `perRoundLimit` 限制总量。
- 按 `next_retry_at` 和创建时间读取任务，先抢占再执行。
- 目录补偿失败不能阻塞对象回收和暂存回收，三条处理线共享预算并保持明确优先级。
- 记录待处理数量、最老任务年龄、成功数、失败数、抢占失败数、租约恢复数和入队失败数。

**通过条件**：调度器启动、停止、手动 `runRound` 和 `dry_run` 行为稳定，单拍耗时有界，既有对象回收回归不受影响。

### 6. 实现各操作类型的幂等执行器

**目标**：按最终状态判断成功，避免重试造成误删、覆盖或路径越界。

**工作内容**：

- 为用户目录生命周期、用户可见目录、文件操作涉及目录、存量迁移和内部修复分别实现执行分支。
- 执行前重新读取数据库条目和物理路径，不使用失败时保存的旧目录快照直接操作。
- 删除类先确认目标仍属于原账号和原操作版本，防止误删后来创建的同名目录。
- 创建类区分“目标已按预期存在”和“只有物理目录存在但逻辑条目不一致”。
- 移动和重命名类同时检查源、目标、后代路径和同名冲突。
- 用户根目录删除和隔离必须重新确认账号状态、活动传输和隔离根边界。
- 暂存、对象和迁移类操作复用现有安全路径校验，不能把用户路径任务写入对象或日志目录。

**通过条件**：每种操作类型都有成功、目标已完成、路径不安全、源状态变化、目标冲突、权限失败和 IO 失败场景。

### 7. 接入所有失败入口

**目标**：让实际目录操作失败都进入统一队列。

**工作内容**：

- 接入用户目录创建、补齐、删除和隔离。
- 接入目录创建、删除、重命名、移动和父目录准备。
- 接入文件移动、文件重命名、分享接收中涉及的目录准备。
- 接入暂存转正、回退、暂存清理、对象目录准备和对象清理。
- 接入存量迁移、目录条目级联修复、孤儿目录和隔离项清理。
- 对只读列表、切换、选择器和路径校验保留原错误处理，不创建无实际磁盘动作的补偿任务。

**通过条件**：故障注入覆盖每个入口，均能生成正确 `operation_type` 和完整参数，入队失败能被观察到。

### 8. 建立测试和验收

**测试顺序**：先写能复现缺失行为的失败测试，再实现对应代码，最后执行回归。

**自动化测试**：

- 数据库迁移和表约束测试。
- 各操作类型任务插入、去重、抢占、租约过期、成功删除和失败重排测试。
- 幂等测试，覆盖目标已存在、目标已删除、源已变化、同名重建和部分成功。
- 路径边界、跨账号、绝对路径、`..`、符号链接和伪造账号测试。
- 多实例并发抢占测试。
- 调度器每拍和每轮限速测试。
- 磁盘权限、文件占用、数据库短暂失败和进程重启恢复测试。

**回归验证**：

- 现有服务端构建和既有回收调度器测试。
- 协议边界测试，确认无新增或重排协议编号。
- 真实 MySQL 单实例顺序验证，确认夹具数据和清理范围。
- GUI、真实客户端和生产目录验证按实际执行结果单独记录。

**通过条件**：需求中的操作类型均有测试映射，关键失败路径能够入队并恢复，既有文件对象回收无回归，未执行项目明确标记为未验证。

## 风险、恢复与交付门槛

- **迁移风险**：表结构或索引错误会阻止服务启动。恢复方式是按迁移工具提供的逆向脚本回退版本，并在回退后重新执行 schema 检查。
- **误操作风险**：同名目录和任务过期可能造成误删。必须以账号、条目标识、操作版本和路径边界共同确认，不能只按路径存在性执行。
- **并发风险**：租约实现错误可能产生重复执行或旧实例覆盖。需要并发注入和进程退出恢复测试作为交付门槛。
- **积压风险**：永久重试可能造成队列持续增长。必须提供积压指标、最老任务年龄和失败原因日志。
- **兼容风险**：配置缺失或旧数据库未迁移时不能静默启用新处理线。配置和 schema 均应采用现有保守回退或 fail-fast 约定。

完成条件是代码、迁移、测试和本记录同步交付，相关构建与测试实际通过，未验证项和剩余风险已列明。当前计划尚未进入实现阶段。
