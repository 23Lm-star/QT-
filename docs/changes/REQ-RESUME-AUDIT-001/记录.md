# REQ-RESUME-AUDIT-001｜断点续传审计整改

## 目标与当前进展

针对断点续传实现的审计结论（见同目录 [断点续传分析报告.md](断点续传分析报告.md) 与 [最小修改建议.md](最小修改建议.md)）实施核心整改。经两轮讨论裁决：P0-1 按"续传起点 = min(.part 物理大小, upload_session.confirmed_offset)"实施；P0-2 实施摘要保留与回填；P0-3 成功判据收敛为"**逻辑条目建成即成功（含去重复用既有对象），条目未建成必须让客户端可见失败**"。M5/M6/M7 按裁决降为可选项，未实施。

当前进展：**已完成**。M1/M2/M3/M4 全部实施，服务端定向验证 15/15 通过，两端编译通过。

## 计划与重要决定

1. **M1（P0-1）**：`ResumableUploadSession::beginStaged` 增加 `confirmedCap` 参数，续传起点按 `min(物理大小, confirmed_offset)` 封顶；新增静态 `stagedPathFor` 供调用方在建会话前先查会话行。物理超总长整文件重传；`[offset, existingSize)` 残留由后续分块按绝对偏移覆写，无需额外截断。全部 4 处 `beginStaged` 调用形态统一接入（29 非采纳、29 采纳（adopt，经 `PendingFastcheck.offset` 携带 97 的已确认偏移）、97 重放、101 群）；**无可复用会话行时 cap=0（Truncate 重建）**，不按物理续传。
   - 讨论裁决：不是"只读 DB"——TTL 回收器会删 expired/failed 的 `.part` 而保留可复用行（reclaimscheduler 有意不保护、复用查询不过滤 expires_at），物理落后 DB 的方向同样存在，min 同时防住两向。
2. **M2（P0-2）**：`findReusableUploadSession` 扩展为返回 `session_id, confirmed_offset, client_sha256`；29/101 复用分支把行内摘要回填 `ctx.expectedSha`（转正比对读内存副本，不读列，两步缺一不可）；`restartUploadSession` 摘要为空时跳过 `client_sha256` 列，不再写 NULL。97 恒带摘要，不受影响。
3. **M3（P0-3）**：最终 32（`DeferredDataAck32`）改用提交结果 `r.ok`（原为写盘结果）；新增 `DeferredInit30`——29 的暂存已在尾部（0 字节/断点到尾）时 30 不再即时回 complete，转正落定后按提交结果迟到补发。中间块 32 维持异步即时，不变。`HashFinishAction` 补 `ackComplete`。
   - 用户定义对齐：去重命中（引用别人已传对象）本来就回成功，零变化。
4. **M4（客户端防线）**：`Uploader` 校验 32 回带偏移严格连续（`nextOffset == 本块起点+长度`），读块前显式 `seek(m_nextOffset)`；跳跃/回退一律失败收口。
5. **可观测性**：`UploadWriteTask` 写盘失败补 `qCWarning(lcFs)`（原完全静默）；31 守卫拒绝补 `qCDebug(lcNet)` 字段级归因（debug 级，生产默认关）。
6. 未改协议字段、未改表结构、未改 web/ 目录。

## 独立审计与整改（2026-11-14，三个只读子代理）

三份审计结论：服务端核心逻辑——无确认缺陷，核心整改与业务规则一致；客户端/协议一致性——通过，32 应答组合穷举无假成功/卡死/误报；验证有效性——**探针判别断言真实，但文档存在 4 处失实**。据此已修复：

1. **无复用行时起点按物理续传（与裁决"无行按 0 重建"不一致）**：三处调用点 cap 缺省改 0；验证代理确认改前实现为 cap=-1 按物理续。新增判别用例 T1c（.part 2000B 残留+无行 → 起点 0）。
2. **29 adopt（同连接 97→29 采纳）路径未封顶**：`PendingFastcheck` 增加 `offset` 字段（97 登记时写入 `receivedSize()`），adopt 以其为 cap；判别意义有限（adopt 必带摘要、转正复算兜底）但消除"全部调用点统一接入"的例外。
3. **`finalizeUploadOnComplete` 早退漏网**：仅"上下文缺失"早退（deferred=false）时会沿用写盘成功值假成功（正常流程不可达），补防御分支按失败收口（mytcpsocket.cpp）。
4. **文档失实修正**：记录.md 原"T1b 物理落后方向"行对应了不存在的用例（已删除——物理落后方向 min 与改前行为一致，本就无判别点，如实说明）；"三个调用点统一接入"改为准确表述；探针 15/15 的构成（环境类+判别类）如实标注；T2 补起点断言；探针死代码清理。
5. **采纳的审计建议**：`restartUploadSession` 29/101 两处返回值检查补告警（原失败静默）。
6. **记录在案未实施**（非阻塞）：97 lambda 无条件 `expectedSha=shaHex`（当前"97 恒带摘要"前提不触发）；`totalSize==0` 且 `.part` 超长残留不 Truncate（转正大小守卫自愈）；errnoMsg+finished 双信号导致失败文案被泛化覆盖；僵尸 ctx 与 60s 内"继续"重试的竞态（转正复算兜底，损失一轮尝试）。

## 审计与最终结论

- **已修复**：P0-1 续传起点错位（物理超前方向 + 无行收紧）、P0-2 续传丢摘要、P0-3 转正失败不可见（32 与 30 两条通道，含失败通道判别用例 T3c）。

- **已知残留（用户裁决降级为可选，未实施）**：群/个人暂存键共用（P1-2）、同账号跨连接无互斥（P1-3）、无摘要会话的内容身份兜底（M7）、verifying 状态可复用的双提交窗口（P2-2）、长文件名 31 字节截断（P1-5）。
