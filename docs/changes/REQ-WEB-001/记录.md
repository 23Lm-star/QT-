## 计划与重要决定

- 网关纯字节管道，不解析 PDU；每条 WS 连接 1:1 独占一条到 Server 的 TCP 连接（认证态是连接级内存状态，不可池化）。
- u64（transfer_id/file_size）前端一律 BigInt；SHA-256 大文件用 hash-wasm 增量、放 Web Worker；MD5 用 js-md5（Web Crypto 无 MD5）。
- 登录哈希链必须逐字节复刻桌面端，M1a 第一件事核实。
- 断点续传仅会话内有效，不承诺跨页面刷新恢复；语义与桌面端一致（服务端 confirmed_offset/秒传兜底）。
- 公网必须走 TLS（隧道 WSS）；弱密码哈希、无 token 等安全欠账不在本需求内修，登记 TODO。

### M1a 核实结论（源码依据，网页端须逐字节复刻）

- **密码哈希链 = `MD5(password.toUtf8()).toHex()`**（32 位小写 hex），依据 [client.cpp:32-35](../../../Client/client.cpp)。**不是 SHA-256**（Plan 阶段的该假设已纠正）；服务端另有加盐 MD5 仅用于落库，与线上协议无关。
- **PDU 帧**（76B 头，小端，`mkPDU` 全零初始化）：`uiTotalLen`(u32@0)=76+uiMsgLen、`uiMsgLen`(u32@4)、`uiType`(u32@8)、`caData[64]`(@12)、`caMsg[]`(@76)。
- **注册请求(1)**：caData[0..31]=用户名 UTF-8+NUL 补零(≤31B)；caData[32..63]=MD5 hex 恰好 32B 无 NUL；caMsg=验证码 UTF-8+结尾 NUL；uiMsgLen=captcha+1。
- **登录请求(3)**：同注册 caData 布局；caMsg=验证码+NUL+32B clientId(无结尾 NUL)；uiMsgLen=captcha+1+clientId。clientId=QUuid Id128(32hex) 持久化，网页端用 localStorage 生成一次复用。
- **验证码请求(44)**：空 PDU。**响应(45)**：caData[0..3]=status(0 成功/-5 冷却/-6 锁定)，[4..7]=剩余秒；成功时 caMsg=验证码文本，客户端回显（桌面用 placeholder）。
- **登录响应(4)**：caData[0..3]=ret(1 成功/-1 账密错/-2 验证码错/-3 过期/-4 锁定)，成功时 caData[32..63]=登录名(NUL 补零)，-4 时 [4..7]=剩余秒。**注册响应(2)**：ret 非 0 且非 -2/-3/-4 即成功，caData[32..63]=注册名。
- **心跳(50)**：空 PDU；响应(51) 仅刷新存活时间戳。心跳固定 30s。
- **分帧**（客户端 recvmsg）：累积缓冲，while ≥76 读 uiTotalLen，缓冲 ≥uiTotalLen 则派发一帧并移除该长度。发送即写 uiTotalLen 字节。

### M2a 核实结论：好友与私聊（命令 5-18）

- **私聊 push 是类型 15**（服务端 `chat()` 持久化后 `reseed` 原帧转发给接收人，caData[0..31]=发送者），**对发送者无任何响应**（16 从未被服务端发送）→ 网页端发送即忘 + 本地回显；桌面端本就不回显自己消息，网页端回显属有意增强，已在此登记。
- **加好友（9）无可靠响应**：目标在线 → 服务端不直回、push 9 给目标（caData[0..31]=申请人）；目标同意 → 目标发 10（[0..31]=同意人、[32..63]=申请人）→ 服务端把结果 10（caData[0..3]=ret）**push 给双方**；仅目标不在线/已是好友等（ret≠1）才直回 10 给申请人（-2=不在线）。故 9/10 一律走 push 事件，不做请求-响应匹配；拒绝无协议消息（与桌面一致）。
- **Msg 记录布局**（15 push 的 caMsg、18 历史的连续记录）：totalLen u32@0 = 41+正文字节；msgLen u32@4 = 正文字节+1（含 NUL）；Time[30]@8 = "yyyy-MM-dd HH:mm:ss" 本地时间；正文@38；记录尾 2 字节填充；历史迭代 dis += totalLen。
- **正文上限 109 字节（UTF-8）**：服务端读缓冲 120、桌面接收缓冲 110 且无长度校验（TODO 已登记存量面）；网页端发送侧强制 ≤109 字节避免打爆桌面端。
- **在线列表（7→8）/好友列表（11→12）**：caMsg = N×32 字节定长名数组；服务端在线列表已排除请求者本人。
- **删好友（13→14）**：请求 caData[0..31]=被删者、[32..63]=自己（服务端按连接身份覆写"自己"字段，9/15/17 同理）；响应 caData[0] 仅 1 字节 bool；成功后服务端联动清除双方私聊记录 → 网页端须同步清空该会话。
- **历史（17→18）实为"未投递收件箱补发"**：请求 caData[0..31]=自己、[32..63]=对方；服务端只查 `seed_name=对方 AND rev_name=我 AND issuccess=0` 的行，同一事务内标记已投递——在线收到的消息（push 15）入库即 issuccess=1 不会重复下发；自己发出的消息永不出现在自己的 18 响应里。记录内虽无发送者字段，但查询是单向的 → **补发消息发送者必为对方**。~~网页端以中性"历史消息"样式展示~~（已被 2026-10-24 用户验收反馈取代，见下）。
- 另核实：46→47 用户信息响应 caData[0..3]=resultCode(0 找到/-1 未找到)、[4..7]=在线态、[32..63]=用户名。

### M3 用户验收反馈与修复（2026-10-25）

用户人工验收 M3 后报告：**下载过程中点"暂停"，后续链路出现"下载失败"**（1.5GiB bigfile.txt 场景；桌面遗留两个 0 字节 `bigfile(1)/(2).txt` 下载产物）。分析定位出传输引擎 4 个缺陷并修复（`stores/transfer.js` 重写 + `protocol/client.js` 心跳改造）：

1. **受理窗口僵尸运行体**：在 40→41 受理窗口（或另存为对话框）期间暂停，旧运行体未被唤醒/作废——41 到达后继续执行，而任务状态已"已暂停"导致数据块被状态守卫丢弃，收尾时误报"下载字节数不符"；晚到的 43 还可能把已完成任务翻成失败。修复：dlState 引入 **epoch 失效令牌**，暂停/取消自增 epoch 并以 `{__stale}` 唤醒 `d41:`/`dlfin:` 等待点，运行体在每个 await 后校验令牌、失效即静默退出（finally 归还并发名额），收尾前后双查令牌防重复保存。
2. **>500MiB（File System Access API）暂停后继续 = 数据损坏**：旧实现继续时重新弹"另存为"，`createWritable()` 把已选文件**截断清零**，FS 模式内存 parts 为空 → 只写尾部字节。修复：**写句柄跨暂停保留**，继续时接着写（不重弹对话框、不截断）；仅真失败/取消才 abort 句柄并清零进度（重试=诚实的整文件重下）。
3. **失败收尾竞态**：catch 中 FS 句柄 abort 后未清内存进度，可能拼出缺前缀的文件。修复：abort 时同步 `doneBytes=0`、parts 清空。
4. **后台标签页心跳被节流踢线**（验证期间新发现）：隐藏标签页中主线程 `setInterval` 被浏览器节流到 ≥1 分钟，30s 业务心跳发不出，超过服务端存活阈值被踢（页面显示"未连接"，下载失败可叠加此因）。修复：心跳定时器移入 **Blob Web Worker**（不受后台节流），Worker 不可用时回退主线程定时器。

### M3 用户复测反馈与修复二（2026-10-25，>500MiB FS 直写路径）

> 已被"修复三"整体取代：FS 直写路径连同本节实现全部删除，下载统一 Blob 化。保留本节仅作缺陷分析记录。

用户复测报告：小文件正常落下载文件夹；logfile.txt（>500MiB）弹"另存为"后**正式文件 0 字节与 .crswap 暂存文件长期并存**，用户删除暂存文件后正式文件仍 0 字节。

机理说明：Chrome File System Access API 固有行为——选定位置即创建/截断正式文件为 0 字节，数据全部先写 `.crswap`，`writable.close()` 时才原子合并。下载中"0 字节正式文件 + 增长的暂存"是正常中间态；**删除暂存即毁掉全部已收数据**。在此之上定位到实现真缺陷：

1. **写盘错误被静默吞掉**：`writeChain` 每环 `.catch(()=>{})`，暂存被删/磁盘错误后所有 write 失败无人知晓，close 后任务仍标"已完成"而正式文件 0 字节/不完整（与用户现象吻合）。
2. **FS 路径无落盘字节核验**：Blob 路径有 `total===size` 硬校验，FS 直写路径没有对应校验。
3. **中间态无提示**：UI 未告知用户 .crswap 是正常暂存、勿删。

修复（`stores/transfer.js` + `TransferPanel.vue`）：
- 写链记录**首个错误**（`ds.writeError`）并跳过后续无效写入；收尾 `await writeChain` 后先查 writeError → 显式失败并给出可操作原因（"写入磁盘失败（.crswap 暂存文件可能被删除/移动，或磁盘错误）"）。
- 新增 `ds.written` 落盘字节计数（含续传复用句柄的累计），收尾核验 `written === size`，不符即失败"落盘字节数不符…拒绝合并不完整文件"——**绝不把坏文件标成已完成**。
- 失败/断线/移除路径统一复位 writable/written/writeError（重试=重弹另存为、整文件重下，诚实语义）。
- FS 下载启动后任务行显示提示："大文件直写所选位置：完成前正式文件显示 0 字节，同目录 .crswap 为写入暂存文件（下载中请勿删除），完成后自动合并"。

验证：重建 dist；受控浏览器 Blob 路径回归（60MiB 上传→下载 11% 暂停→继续→100% 完成，无失败）✅；webfix2 夹具清理复核 0。**FS 直写路径已用 mock `showSaveFilePicker`（主世界注入，写/关闭故障经 DOM dataset 注入）在真实浏览器端到端验证四链路**：
- 成功链路：501MiB 下载 → 任务 100%，mock 记录逐字节 total=525336576、closed=true、aborted=false ✅
- 写失败注入（模拟 .crswap 被删/磁盘错误）：任务**显式失败**"写入磁盘失败（.crswap 暂存文件可能被删除/移动，或磁盘错误）"，句柄 abort、进度归零，绝无假"已完成" ✅（即用户所遇"暂存自己消失+正式文件 0 字节"静默场景的堵截证明）
- 合并失败注入（模拟目标被占用致 close 失败）：任务显式失败并给出"请解除占用后点继续重新下载"；"继续"走重新弹保存位置→整文件重下 ✅
- 故障恢复：清除注入后"继续"→ 100% 完成、closed=true ✅
真实磁盘上的 .crswap 行为为 Chrome 原生语义（下载中 0 字节正式文件+暂存并存属正常，完成后原子合并），任务行已加防误删提示。用户复测建议：对残留 0 字节 logfile.txt 直接选同名覆盖重下即可。

### M3 用户复测反馈与修复三（2026-10-25，下载引擎弃用 FS API、全量 Blob 化）

用户再次复测："依旧不行——没有动暂存文件和原文件，暂存文件自己没了之后原文件还是 0 字节"；并新报"对正在下载的文件任务点取消，只会删除暂存文件（遗留 0 字节正式文件）"。

**根因裁决：修复一的"FS 写句柄跨暂停保留"在真实 Chrome 中根本不成立，修复二只堵住了静默失败、没解决残留。** FS API 的三个 Chrome 固有语义在暂停/继续/取消交互下不可靠：
1. 重新 `showSaveFilePicker` 会创建/截断正式文件为 0 字节；保留旧句柄跨暂停续写则受 .crswap 生命周期影响（暂存被浏览器/磁盘策略回收即全部已收数据丢失，正式文件永远 0 字节——与用户现象吻合）。
2. `abort()` 只删 `.crswap` 暂存，**不删除 picker 已创建的 0 字节正式文件**（用户报的取消残留）。
3. `close()` 合并失败（目标被占用、同步盘、锁定）时同样留下半成品正式文件。

**决定（不再询问，属缺陷根治而非业务取舍）：彻底弃用 File System Access API。所有大小的下载统一为"增量 Blob 聚合 + `a[download]` 浏览器原生保存"**：
- `dlState` 改为 `{blobs, blobBytes, parts, partsBytes, epoch}`；42 到达追加 Uint8Array 进 parts，满 64MiB 滚存为 Blob 段（Chrome Blob 超阈值自动磁盘后备，600MiB 不占等量内存）。

### M3a 核实结论：云盘与传输（命令 19-43、58/59、97/98、107/108）
