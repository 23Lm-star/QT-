# 项目面试 58 项 · 提问清单（含表达脉络）

> 来源：`docs/面试主题/面试-业务功能逐项讲解.md`（58 项原稿，本文只做拆分与重组）
> 用法：面试官按「问法」开口，你照「表达脉络」的顺序讲，讲完接「追问」。追问只给问题、不给答案——答案在原稿对应条目里。

## 怎么用这份清单

| 场景 | 做法 |
|---|---|
| 自测 | 遮住表达脉络，只看问法，看能不能讲出 5 步；讲不出就翻回原稿那一项 |
| 对练 | 让对方只念「问法 + 追问」，不看脉络；你答完再对照脉络，检查漏了哪一步 |
| 记录 | 每答完一项，在追问后面标 ✓ / ✗，✗ 的就是下一轮重点 |
| 优先级 | 13、24、31、40、57 五项最长也最容易被深挖，先练这五项 |

## 全项目口径（开口之前先在脑子里过一遍）

- Qt 5.14.2 / C++11 / MySQL，C/S 结构；桌面端与网页端复用同一套服务端业务。
- 没有生产规模压测结论，不凭代码结构推吞吐量和并发用户数。
- 自研的是内存池；异步写盘和服务端摘要复算用的是 Qt 线程池。
- 口令是「每账号随机盐 + 加盐摘要」，属于密码哈希，不是可逆加密，也不是现代慢哈希方案。
- 私聊与群消息是两套可靠性模型，不能混着讲。
- 认证主体由连接决定，不信报文里自称的账号名。

# 账号与连接（01—08）

> 这段被追问最多。讲的时候先报结论再补细节；凡是当前没做的，主动声明是改进方案。

## 01. 注册账号

**问法**：从用户点下「注册」开始，把整条链路讲一遍，一直到客户端能登录。

**表达脉络**：填表校验发请求 → 拆帧先消费验证码 → 加盐哈希写账号表 → 建目录失败不回滚 → 回应答直接登录

**要讲到的边界**：建立唯一账号及个人云盘的初始目录。成功边界首先是账号记录创建成功，不能把随后尝试创建目录说成与数据库原子提交。

**追问**

1. 账号建成但目录创建失败怎么办？
2. 账号名为什么不能任意字符？
3. 既然知道 MD5 不适合存密码，为什么项目还采用加盐 MD5？
4. 验证码能防住哪些注册滥用，还存在哪些不足，怎样减少限流对正常用户的影响？
5. 两个客户端同时注册同一个名字会怎样？

## 02. 登录账号

**问法**：登录请求到了服务端，到客户端进主界面，中间都发生了什么？

**表达脉络**：取码填凭据发登录 → 消费验证码 → 事务推进版本与在线 → 绑主体先登记再踢旧 → 客户端建登录态 → 每请求校验版本

**要讲到的边界**：把有效凭据转换成当前连接上的可信身份。后续授权依据服务端绑定的身份和版本，不依据报文自称的用户名。

**追问**

1. 为什么不使用访问令牌？
2. 密码正确但数据库提交失败算登录成功吗？
3. 服务端重启还能用旧连接身份吗？
4. 数据库在线标记就是登录凭证吗？
5. 启动对账失败为什么不能继续提供服务？

## 03. 验证码获取与校验

**问法**：验证码这个功能你是怎么实现的？答案存在哪一侧？

**表达脉络**：点取码发请求 → 查锁定与冷却 → 生成答案只发图 → 提交查锁过期匹配 → 通过即消费

**要讲到的边界**：服务端生成图片验证码，为注册、登录增加一次识别校验和频率限制。答案、有效期、错误次数和锁定状态由服务端管理，客户端只展示图片并提交用户输入。图片提高了直接读取答案的成本，但不能据此承诺阻止所有自动化识别。

**追问**

1. 绕开按钮直接发请求呢？
2. 重新建立连接能绕过锁定吗？
3. 输对验证码后密码错了，原码还能继续用吗？
4. 验证码有效期、获取冷却和连续输错锁定怎样测试，怎样避免每次都真实等待？
5. 验证码在登录流程里解决什么问题，有什么局限？

## 04. 退出登录

**问法**：用户点「退出登录」，服务端实际做了什么？

**表达脉络**：点退出清状态关连接 → 断线触发收尾 → 先释放下载流 → 权威连接才写离线 → 撤认证移出连接表

**要讲到的边界**：网页端结束当前会话，保留账号和云盘数据。它与协议里的账号注销有不同的数据后果。

**追问**

1. 为什么没有专门的退出协议？
2. 网络异常导致服务端暂时不知道退出呢？
3. 账号注销和退出登录有什么区别？

## 05. 注销账号

**问法**：你们的「注销」和「退出登录」有什么区别？注销链路怎么走？

**表达脉络**：再输口令发注销 → 拆帧查认证版本 → 事务复核口令删关联 → 提交后清目录靠补偿 → 撤认证同名算新号

**要讲到的边界**：删除当前认证账号的核心记录并撤销会话。当前流程会清理私聊、好友、分享和登录等关联数据，但不能把返回成功解释为所有物理数据和失败补偿都已完成。

**追问**

1. 为什么还要求口令？
2. 磁盘目录删不掉呢？
3. 能借注销接口删除别人的账号吗？
4. 群文件和内容去重对象会一并直接删掉吗？
5. 账号注销会删除什么，什么时候算成功？

## 06. 重复登录互踢

**问法**：同一个账号在第二台设备登录，第一台是怎么被踢下去的？

**表达脉络**：第二端登录过校验 → 事务分配新版本 → 先登记再踢旧连接 → 锁内收集锁外断开 → 旧连接按版本拒绝

**要讲到的边界**：同一账号只保留最新有效会话。目标是旧连接即使尚未物理断开，也不能继续执行新业务。

**追问**

1. 为什么不只用在线字段？
2. 几乎同时登录谁赢？
3. 旧连接正在上传怎么办？
4. 为什么在已经实时踢走过期登录连接的基础上，还需要被动检查过期登录连接，这不是重复操作吗？
5. 互踢会不会把账号本人踢下线？

## 07. 心跳与失联检测

**问法**：客户端怎么判断自己和服务端断了？服务端又怎么清掉僵尸连接？

**表达脉络**：30 秒一发 90 秒判失联 → 服务端记活跃扫僵尸 → 锁内收集锁外关闭 → 权威连接才写离线 → 任务转失败留续传

**要讲到的边界**：识别没有及时反馈的连接，给用户明确失联状态，并回收僵尸连接。超时表示怀疑失联，不证明具体故障原因。

**追问**

1. 为什么不只依赖 TCP 保活？
2. 为什么不直接使用复用客户端请求作为失联的心跳包，而是自己单独设置周期性心跳包发送来检测连接是否失效？
3. 心跳检测的是客户端失联；如果客户端长时间没有任何操作和请求，你怎么判断这条连接还活着？有哪些检测机制？
4. 当前重连之后不能保留之前的登录信息吗？为什么不保留？如果要保留，从 session 角度该怎么做？
5. 旧设备晚一点断开，会不会把新设备也改成离线？

## 08. 手动重连与重新登录

**问法**：断线之后重连，为什么必须重新走一遍登录？

**表达脉络**：失联停任务留快照 → 重连重建通道握手 → 重新取码登录 → 服务端绑新会话 → 按账号重建页面续传

**要讲到的边界**：在断线后恢复连接和新的认证会话，同时保留可解释的任务结果。当前不提供无密码自动会话恢复承诺。

**追问**

1. 为什么采用手动重连？
2. 为什么重连后需要进行重新进行身份认证，为什么不能直接利用之前等登录的身份认证，若是需要利用之前登录的身份认证怎么做(从session方向去说)？
3. 重连过程中又点几次呢？
4. 重连后换了账号呢？
5. 客户端使用长连接还是每发消息重连，支持哪种聊天形式？

# 好友管理（09—12）

> 四条都很短，主线只有一句：申请人和操作者都以服务端认证主体为准，不信报文。

## 09. 在线用户查询

**问法**：在线用户列表是怎么查出来的？

**表达脉络**：发查询请求 → 按主体排除自己和好友 → 查名称与在线 → 返回快照

**要讲到的边界**：查询可添加的陌生用户，并返回查询时的在线状态。在线状态只用于发现和展示，不能作为后续授权依据。

**追问**

1. 在线用户列表能不能作为发消息权限？
2. 在线状态是查询那一刻的快照，返回之后就开始过期，界面怎么处理这种过期？
3. 列表没做分页，在线用户上千时接口会返回什么？
4. 从看到列表到真正加好友之间关系变了，服务端在哪一步重新校验？

## 10. 添加好友

**问法**：加好友的申请，是怎么送到对方屏幕上的？

**表达脉络**：选目标发申请 → 主体定申请人 → 查重登记申请 → 在线通知离线留档 → 接受后建关系

**要讲到的边界**：把陌生账号转为可以私聊的好友关系，申请和接受分成两个阶段。

**追问**

1. 目标离线时能不能加好友？
2. 申请和接受为什么拆成两个阶段？多维护一张申请表换来什么？
3. 在线通知发出去了，但对方一直没点，系统怎么知道这条申请的状态？
4. 重复提交同一个申请，会登记几条记录？
5. 报文里自称的申请人被改掉，会不会替别人发出申请？

## 11. 好友列表

**问法**：好友列表的数据是怎么查的？

**表达脉络**：查关系两侧 → 合并去重 → 关联资料与在线 → 整体刷新列表

**要讲到的边界**：查询已经建立的好友关系，并补充好友资料和查询时的在线状态。

**追问**

1. 为什么要查询两个方向？
2. 一条关系只存一行，每次都要双向查询再合并，规模大了怎么优化？
3. 列表全量返回、没有分页，好友很多时客户端会怎样？
4. 客户端缓存的好友列表能不能当权限用？为什么不能？
5. 在线状态是读取时快照，列表长时间不刷新会误导用户吗？

## 12. 删除好友

**问法**：删一个好友，数据库里动了哪些数据？

**表达脉络**：发删除请求 → 主体定操作者 → 删双方关系 → 再清私聊记录 → 客户端刷新列表

**要讲到的边界**：解除双方好友关系，并按当前规则尝试清理服务端私聊记录。

**追问**

1. 删好友后旧窗口还能发消息吗？
2. 删关系和清聊天记录不在一个事务里，清理失败会留下什么？
3. 本地聊天记录删不掉，要不要清？谁来清？
4. 对方会不会立刻知道自己被删了？
5. 删完之后旧聊天窗口还能发消息吗？

# 好友私聊（13—13）

> 一条顶十条。答这一项必须主动区分「入库成功 / 尝试转发 / 对方收到 / 已读」四种结果。

## 13. 好友私聊

**问法**：一条私聊消息，从你点发送到对方看到，中间经过哪些环节？

**表达脉络**：开窗读本地再补拉 → 事务锁待投递确认后标记 → 发送校验登记后发出 → 覆盖发送人入库配 ID → 在线转发离线补拉 → 按消息 ID 去重落库

**要讲到的边界**：完成文本发送、在线接收、离线补发、本地保存、历史加载与本地清空。每条消息都携带服务端入库时分配的消息 ID：它是消息的唯一标识，接收端的排序和去重都以消息 ID 为准；发送侧的校验去重按“发送人 + 发送时间”匹配。入库成功即视为消息发送受理，之后的投递分为实时转发与离线拉取两条路，接收端成功收到并返回响应后才记录投递成功；没有群消息那样的严格连续序号与补洞机制，入库成功、对方收到、对方已读必须分开说。

**追问**

1. 为什么先保存再转发，而不直接转发？
2. 在线时网络刚好断了，消息会补发吗？
3. 离线补发为什么用事务和行锁？
4. 能不能保证重试不重复发？
5. 私聊去重完全准确吗？

# 群与成员管理（14—23）

> 十项共用一套群信封和幂等键。先把信封讲清楚，后面每项只讲差异。

## 14. 创建群

**问法**：建群的完整链路讲一下。

**表达脉络**：校验群名取请求号 → 入口判重丢弃重发 → 事务建群加群主 → 回包带群标识 → 超时拉列表核对

**要讲到的边界**：建立群，并同时赋予创建者群主身份，避免出现“群已创建但没有群主”的半成品。建群请求先过连接级群请求号判重：建连后双方记录都置 0，第一个群请求从 1 起编，之后每个动作加 1。同一次动作的重发沿用原号（避免重复执行，代价是拿不到结果），已经收到失败应答后的新尝试必须换新号；服务端只受理大于记录值的号，受理后把记录更新为该号，同号或更小的重发直接丢弃、不执行建群事务。

**追问**

1. 为什么不先建群再异步加群主？
2. 群名相同算重复群吗？
3. 响应丢了，重发创建一定不会多建吗？
4. 创建者身份能由报文字段指定吗？
5. 自己填写另一个群标识，能直接操作那个群吗？

## 15. 查看、刷新自己的群列表

**问法**：群列表怎么查、什么时候刷新？

**表达脉络**：登录刷新取号请求 → 判重后查有效成员关系 → 关联群表排序返回 → 客户端整体替换

**要讲到的边界**：返回当前账号仍具有效成员关系的群，并展示其群状态和角色。查询范围不是所有群，也不是只依赖客户端缓存。群列表请求同样带群请求号，重复刷新只会执行一次，不会叠加多次查询和多次渲染。

**追问**

1. 为什么通知后还查询？
2. 漏掉一次通知怎么办？
3. 退出群后缓存还在呢？
4. 群特别多怎么办？
5. 分页会影响权限吗？

## 16. 查询群摘要

**问法**：群摘要里放什么？为什么要单独做一个接口？

**表达脉络**：选群取号请求 → 判重验成员身份 → 只读查摘要 → 回包刷详情

**要讲到的边界**：获取指定群的简要信息，供界面展示和后续状态同步使用。摘要查询仍是受成员权限约束的业务读取，请求同样经群请求号判重。

**追问**

1. 为什么不用群列表里的数据？
2. 能保证名称和成员数来自同一瞬间吗？
3. 群被解散后如何处理？
4. 成员数能直接由客户端列表长度计算吗？
5. 只知道群标识能直接查询群摘要吗？

## 17. 邀请用户入群：完整链路

**问法**：邀请一个人进群，从发起邀请到他进群，完整链路是什么？

**表达脉络**：取号加幂等键发邀请 → 判重锁群验角色 → 幂等键命中回放未命中落库 → 受邀人补查待处理 → 接受前反查群复核期限 → 事务建成员关系

**要讲到的边界**：覆盖发起邀请、待处理查询、接受或拒绝、成员建立与通知。邀请是有身份、状态、到期和幂等规则的持久化业务，不只是弹一个确认框。去重分两层：群请求号挡同一次动作的重发，邀请幂等键保证同一邀请不被重复创建并回放原结果。

**追问**

1. 为什么不直接把人加入群？
2. 连续点击邀请会发多份吗？
3. 接受时群已经解散呢？
4. 别人拿到邀请标识能替我接受吗？
5. 邀请入群怎样设计角色权限矩阵，并测试与解散、重复接受同时发生的情况？

## 18. 查看群成员列表

**问法**：群成员列表怎么拉？成员变动后界面怎么同步？

**表达脉络**：取号发成员请求 → 判重验成员 → 全量查角色按加入时间 → 回包逐条校验更新 → 事件触发重查

**要讲到的边界**：让有效成员查看群内当前有效成员及角色，为邀请、移除和转让等管理操作提供选择依据。成员列表请求同样带群请求号，重复请求只会执行一次。

**追问**

1. 为什么不返回所有历史成员？
2. 界面禁用了按钮还要服务端检查吗？
3. 群成员非常多呢？
4. 管理员能看到的列表和普通成员有区别吗？
5. 群成员变化以后，其他客户端怎样知道？

## 19. 退出群

**问法**：退出群的规则是什么？群主能直接退吗？

**表达脉络**：确认退出取号 → 事务锁群校验成员 → 群主须先转让解散 → 关系改已退出占序号 → 提交发事件断增量

**要讲到的边界**：结束本人有效成员关系并立即收回后续群操作权限，保留必要历史。群主必须先转让或解散，不能直接留下无主群。退出请求按群请求号判重，同号重发不会重复改写成员状态。

**追问**

1. 为什么用状态而不删除成员行？
2. 群主为什么不能像普通成员一样退？
3. 退出前的下载一定立即停止吗？
4. 重复退出怎么办？

## 20. 移除群成员

**问法**：踢人怎么实现？权限怎么判？

**表达脉络**：选目标取号请求 → 判重锁群验角色 → 目标须有效普通成员 → 改状态追系统消息推版本 → 被移除者单独回包

**要讲到的边界**：允许有管理权限的人移除普通成员，限制越级管理。当前群主、管理员都不能通过该分支直接移除管理员或群主。移除是写操作，请求先经群请求号判重，同号重发不会改两次成员状态。

**追问**

1. 为什么不能让管理员互相移除？
2. 群主想移除管理员怎么办？
3. 目标恰好被升为管理员呢？
4. 移除会删除目标发过的消息吗？
5. 被移除的人还开着旧窗口，能继续管理或查询群吗？

## 21. 设置成员角色

**问法**：群里的角色是怎么建模的？改角色要注意什么？

**表达脉络**：选目标角色取号 → 判重验群主 → 枚举角色改目标 → 查命中行推版本 → 事件回包重读列表

**要讲到的边界**：由群主调整其他有效成员在管理员和普通成员之间的角色。不是任意修改角色字符串的通用接口。角色变更请求同样先经群请求号判重。

**追问**

1. 为什么不用一条通用角色修改接口处理转让？
2. 管理员能再任命管理员吗？
3. 界面已显示管理员，后续请求还能按旧身份处理吗？
4. 重复设置同一角色会怎样？
5. 为什么权限不放在客户端？

## 22. 转让群主

**问法**：转让群主为什么必须放在一个事务里？

**表达脉络**：选目标取号请求 → 判重锁群验群主 → 目标升原主降同一事务 → 任一失败回滚 → 结果靠查询确认

**要讲到的边界**：在保留群的前提下更换唯一负责人。当前规则是目标升为群主，原群主降为管理员。转让请求同样先经群请求号判重，同号重发不会执行第二次角色转移。

**追问**

1. 为什么原群主降为管理员而不是退出？
2. 目标在点击后先退出了怎么办？
3. 两次转让同时到达呢？
4. 提交成功但响应丢失呢？
5. 群主转让到一半失败，会不会留下两个群主？

## 23. 解散群

**问法**：解散群之后，数据是怎么处理的？

**表达脉络**：确认解散取号 → 判重锁群验群主 → 只切状态推版本 → 周期任务分批清引用 → 写全拒读按群状态

**要讲到的边界**：由群主终止群的正常写业务。解散请求本身只把群状态切到已解散，相关数据清理交给周期性任务分批分阶段完成，而不是在解散事务里一次删完。解散是写操作，请求先经群请求号判重。

**追问**

1. 为什么不立即物理删除？
2. 解散后群文件引用不清理会怎样？
3. 解散后还能上传或删群文件吗？
4. 解散与发消息并发呢？
5. 解散后历史群消息是否自动删除？

# 群消息（24—24）

## 24. 群消息：完整链路

**问法**：群消息的可靠投递是怎么做的？和私聊有什么不同？

**表达脉络**：开窗取水位定补拉起点 → 校验取号带幂等键 → 判重锁群命中回放未命中配 seq → 先提交再广播 → 按 seq 合并缺号补拉 → 连续前缀落库与报已读

**要讲到的边界**：把群文本发送、持久化、在线推送、历史补拉、幂等重试、连续已读、本地记录统一起来。优先保证群内顺序、可补齐和可解释的成功语义，不承诺跨群全局顺序或无限规模广播。三层编号各管一件事：群请求号管这次请求要不要执行，`client_msg_id` 管同一条消息不重复创建并回放原序号，群内 `seq` 管顺序、补洞与已读。

# 文件传输与任务管理（31—44）

> 十四项是一套状态机，用「任务从创建到收敛」串起来，不要逐项背。

## 31. 个人文件上传

**问法**：一个文件从选中到出现在云盘里，中间经过哪些步骤？

**表达脉络**：建任务算摘要 → 预检命中不发正文 → 未命中初始化拿起点 → 按确认偏移停等分块 → 复算转正建条目 → 收结果刷新列表

**要讲到的边界**：把本机普通文件变成当前账号可见的云盘条目，包含排队、摘要预检、分块写盘和最终转正，不只是把字节发到服务端。

**追问**

1. 为什么使用暂存文件？
2. 为什么不一次把文件读进内存？
3. 写盘放线程池就完全不阻塞吗？
4. 最后一块成功就能证明完整上传吗？
5. TCP 可靠，为什么还要应用层 ACK？

## 32. 个人文件下载

**问法**：下载的完整链路讲一下。如果客户端收得慢，服务端会怎样？

**表达脉络**：建任务发初始化 → 服务端验权开流 → 轮转发块背压限流 → 按传输 ID 写本地 → 完成通知收尾释放

**要讲到的边界**：将本人有权访问的云端普通文件保存到本机，按任务分流并处理失败、续传和最终完成。目录不直接作为普通文件下载。

**追问**

1. 为什么流式发而不一次写到套接字？
2. 本地磁盘满了怎么办？
3. 相同大小就说明内容没错吗？
4. 网页和桌面下载为什么不同？
5. 下载读 64KiB 也是阻塞 IO，为什么不放池？

## 33. 秒传

**问法**：秒传的判定依据是什么？凭什么相信这个文件真的存在？

**表达脉络**：算摘要发预检 → 会话回放防重复 → 摘要加大查对象 → 事务建条目加引用 → 未命中走普通上传

**要讲到的边界**：对已存在的相同内容复用物理对象，只创建当前用户或群的引用，减少正文传输与重复存储。命中检查不等同于证明用户确实持有内容。

**追问**

1. 为什么不用文件名和大小？
2. 客户端随便报摘要能蒙混吗？
3. 为什么不做内容持有挑战？
4. 为什么不用 MD5 做秒传？
5. 只比较文件名行不行？

## 34. 上传断点续传

**问法**：上传到一半断了，重连之后是接着传还是重传？

**表达脉络**：保资料换 ID 重排队 → 重新初始化 → 服务端按暂存定起点 → 严格连续分块写盘 → 中止截回确认位置

**要讲到的边界**：重新初始化后从服务端认可的位置继续，避免重传完整文件。不是用客户端已发送字节数，也不支持任意跳跃和乱序填洞。

**追问**

1. 为什么不能相信客户端进度条？
2. 服务端数据库偏移与文件大小谁绝对权威？
3. 已确认写入能抵抗断电吗？
4. 源文件被用户改了呢？
5. 上传的 32 会不会被下载块饿死？

## 35. 下载断点续传

**问法**：下载的断点续传是怎么做的？

**表达脉络**：查分片读真实大小 → 换 ID 重新鉴权 → 服务端核范围给偏移 → 新数据才可追加 → 旧轮次数据丢弃

**要讲到的边界**：利用本机已有分片重新请求后缀，降低失败重下成本。当前以实际分片长度决定起点，缺少内容版本及分片摘要的完整绑定。

**追问**

1. 为什么不保存每块下载偏移？
2. 分片被手工删除呢？
3. 服务端文件变了呢？
4. 续传起点超出文件大小怎么办？
5. 下载中途退出后，怎样验证续传位置有效，分片过长、被修改或源内容变化怎么办？

## 36. 暂停传输任务

**问法**：暂停一个传输任务，具体做了哪些事？

**表达脉络**：面板点暂停 → 停收发撤 ID 映射 → 发释放请求 → 在途延迟中止 → 归还名额存快照

**要讲到的边界**：暂时停止一个任务，释放并发名额，并保留继续所需数据。暂停不是断开整条业务连接。

**追问**

1. 为什么不关闭 TCP 连接？
2. 能让在途字节立即消失吗？
3. 暂停与完成、断线或迟到确认同时发生时，怎样测试任务不会卡死或重新启动？
4. 暂停时正在写盘怎么办？
5. 暂停一个任务，会影响其他任务吗？

## 37. 继续传输任务

**问法**：继续一个任务，为什么不能沿用原来的传输编号？

**表达脉络**：检查状态换 ID → 重新排队预检 → 服务端重新鉴权给起点 → 按起点恢复收发 → 同一任务行更新

**要讲到的边界**：把暂停或允许恢复的失败任务重新送入调度，并重新确认传输条件。它不是恢复旧套接字里未完成的一次回调。

**追问**

1. 为什么继续后还会排队？
2. 暂停期间群被移除了呢？
3. 旧的确认晚到怎么办？
4. 继续操作与重复点击、取消或断线交错时，怎样验证不会重复入队或同时启动两轮？

## 38. 取消传输任务

**问法**：取消和暂停的区别是什么？取消之后数据怎么处理？

**表达脉络**：确认取消清队列 → 发释放停收发 → 上传对齐暂存下载删分片 → 任务终止不复活

**要讲到的边界**：结束用户对该任务的继续意图，并回收客户端任务资源。服务端暂存内容不等于同步从磁盘立刻彻底删除。

**追问**

1. 为什么不马上删服务器暂存？
2. 取消后还能收到数据吗？
3. 取消和服务端完成撞在一起呢？
4. 为什么不直接删除整个下载目录？
5. 取消与服务端完成、后台摘要回调同时发生时，怎样验证任务不会复活或误删文件？

## 39. 失败任务重试

**问法**：失败任务重试，怎么避免重复数据或重复挂接？

**表达脉络**：原任务键定位 → 核对源与分片 → 换 ID 清失败原因 → 重新走完整初始化 → 服务端定回放或重传

**要讲到的边界**：重新尝试一个失败业务任务，尽可能利用保留数据，同时重新验证失败原因是否已消除。

**追问**

1. 重试会建重复文件吗？
2. 重试旧错误还能留着吗？
3. 只重试网络发送够吗？
4. 失败重试与连续点击、再次断线同时发生时，怎样测试状态和名额不会失控？
5. 为什么下载的继续和重试采用相似流程？

## 40. 多任务排队与有限并发

**问法**：为什么要限制 3 路并发？这个限制是怎么落地的？

**表达脉络**：建键入队 → 按方向限 3 路 → 服务端硬性再限 → 下载轮转上传停等 → 结束归还名额

**要讲到的边界**：把大量任务限制为有上限的同时活动任务，兼顾吞吐、内存和交互响应。单连接上传三路、下载三路，个人与群共享对应方向额度。

**追问**

1. 单连接并发会完全互不影响吗？
2. 为什么服务端也要限流？
3. 一个慢下载会无限占发送缓冲吗？
4. 为什么摘要也要占名额？
5. 你怎样评价当前控制模型，最稳妥和最需补强的分别是什么？

## 41. 传输任务面板

**问法**：传输任务面板上的进度和速度，数据是从哪来的？

**表达脉络**：管理器持状态 → 面板订阅只展示 → 进度分确认与接收口径 → 按钮只传意图 → 变化信号驱动刷新

**要讲到的边界**：让用户看清每个任务的方向、进度、状态和失败原因，并能针对单任务控制。面板显示必须对应真实状态。

**追问**

1. 为什么不让每一行自己管理上传器？
2. 进度到百分之百为何还不一定完成？
3. 失败后为什么保留任务行？
4. 刷新越频繁越好吗？
5. 实际测过哪些传输指标，吞吐、平均延迟、P95/P99、错误率和资源占用分别说明什么？

## 42. 未完成任务保存与恢复

**问法**：关掉客户端再打开，未完成的任务怎么恢复？

**表达脉络**：按账号存快照 → 只存意图线索 → 切号分区合并 → 恢复成暂停态 → 继续时重走链路

**要讲到的边界**：桌面端保存未完成任务的意图，重启或再次登录后恢复可继续的任务。快照不是服务端字节进度或认证凭证的副本。

**追问**

1. 为什么不持续保存每个字节进度？
2. 为什么恢复成暂停？
3. 写快照过程中进程崩溃呢？
4. 网页刷新页面后，未完成的上传也能像桌面端一样从快照恢复吗？
5. 为什么恢复不复用 id？

## 43. 断线时收敛任务状态

**问法**：断线的时候，正在跑和正在排队的任务分别怎么处理？

**表达脉络**：断线先停调度 → 运行任务转失败还名额 → 排队暂停保原状 → 迟到回调找不到就丢 → 重连解除阻断

**要讲到的边界**：网络已不可用时，让任务及时退出正常传输状态并释放名额，避免永久显示“进行中”。保留恢复材料但不假装自动成功。

**追问**

1. 为什么不把所有任务都删掉？
2. 后台计算回来了会不会把失败改成功？
3. 服务端来不及收到中止怎么办？
4. 重连后第四个任务为什么可能能开了？
5. 为什么不直接扩大队列？

## 44. 上传内容完整性校验

**问法**：上传完成之后，怎么确认传上去的内容没坏？

**表达脉络**：初始化存声明 → 收完释放句柄 → 线程池复算摘要 → 回主线程核中止 → 事务建对象和条目 → 失败回滚搬回暂存

**要讲到的边界**：在新内容转正之前检查实际收到的总大小和摘要，防止客户端声明与真实文件不一致。它校验内容一致性，不判断文件是否安全或是否归用户所有。

**追问**

1. 为什么不在网络线程同步算？
2. 为什么释放别名句柄？
3. 数据库失败时文件已经搬到正式区呢？
4. 摘要一致就能证明没有恶意文件吗？
5. 如何补测，才能证明线程池改善了系统响应，而不只是把等待挪到队列？

# 群文件（45—48）

> 和个人文件的差异只有三点：双条目、共享配额、群状态校验。

## 45. 查看群共享文件列表

**问法**：群共享文件列表怎么查？

**表达脉络**：取号带页参请求 → 判重验成员 → 按引用查群文件 → 分页返回更新列表

**要讲到的边界**：让有效群成员按群查看共享文件、上传者及分页信息。群文件列表不能复用个人路径检查替代成员检查；群文件请求共用群协议信封与群请求号判重。

**追问**

1. 为什么按引用而非对象列文件？
2. 为什么不一次返回全部？
3. 解散后可读是否意味着所有群接口可读？
4. 群文件列表和个人云盘列表有什么不同？

## 46. 上传群文件

**问法**：上传群文件和个人上传，链路有什么不同？

**表达脉络**：群初始化判重验成员 → 命中直接挂双条目 → 未命中暂存分块 → 复算先个人后群引用 → 挂接失败要撤销

**要讲到的边界**：把成员的本地内容发布为指定群可见文件，复用个人传输机制，但增加群权限和群引用提交。群上传初始化同样带群请求号，重发被丢弃，不会重复创建上传上下文。

**追问**

1. 为什么不把文件复制到每个群目录？
2. 普通成员也能上传吗？
3. 上传中被移除或群被解散呢？
4. 个人和群同名文件会覆盖吗？
5. 群文件上传会不会和个人上传互相覆盖？

## 47. 下载群文件

**问法**：下载群文件走的是哪条链路？

**表达脉络**：群下载请求判重验成员 → 验引用归属定对象 → 回元数据建流 → 收正文与完成通知

**要讲到的边界**：从指定群的文件引用获得有权访问的内容，并复用下载、暂停和续传能力。仅知道物理对象标识不构成权限；下载元数据请求同样经群请求号判重。

**追问**

1. 把别的群文件号塞进来会怎样？
2. 为什么复用个人下载协议正文？
3. 下载开始后被踢出群，正在发送的内容立刻停止吗？
4. 群文件删除后已经打开的下载呢？
5. 成员被移出群后，怎样验证缓存的群文件列表和下载续传不能继续赋予权限？

## 48. 删除群文件引用

**问法**：删除一个群文件，物理文件会被删掉吗？

**表达脉络**：确认删除取号 → 判重验成员 → 事务锁条目验权限 → 改状态减引用 → 回包重查列表

**要讲到的边界**：取消某文件在群中的可见引用，维护共享对象安全。当前权限是群主可删任意群文件，上传者可删自己上传的文件。删除请求先经群请求号判重。

**追问**

1. 管理员可以删除所有群文件吗？
2. 为什么不让所有成员删除？
3. 检查权限后、真正删除前角色变了呢？

# 好友分享与分享链接（49—54）

> 主线是「授权先登记、接受时校验、成功后消费」，以及链接存的是令牌摘要。

## 49. 向好友发送文件分享邀请

**问法**：把文件分享给好友，怎么防止对方伪造路径去拿别人的文件？

**表达脉络**：选文件选好友发请求 → 主体定位源条目 → 登记待接受授权 → 在线推送离线靠接受时校验 → 同意才挂接

**要讲到的边界**：把自己的普通文件分享意图发送给选中的用户，可一次选择多个好友。发出邀请不等于目标已经接收，也不等于对方云盘已建好文件。

**追问**

1. 为什么不发起时就直接塞到对方目录？
2. 所有接收者都会收到吗？
3. 服务端重启后待接受记录还在吗？
4. 从好友列表选人就说明服务端已严格检查好友关系吗？
5. 两种分享都只允许好友吗？

## 50. 接受好友分享并存入自己的云盘

**问法**：好友接受分享之后，文件是怎么进到他云盘里的？

**表达脉络**：接受发请求 → 主体定接收者和目录 → 查有效授权再定位源 → 挂条目加引用不复制 → 成功才消费授权

**要讲到的边界**：在验证真实邀请后，为接收者建立自己的云盘条目，解决重名且不影响源文件。文件条目通常只增加引用，不复制完整正文。

**追问**

1. 伪造接受报文能下载任意文件吗？
2. 分享后源被删了呢？
3. 为什么文件条目不复制？
4. 重名文件怎么选最终名字？
5. 分享重复接受、源文件被删、接收者已有同名内容时，怎样测试保存结果和引用数？

## 51. 生成文件分享链接

**问法**：分享链接的令牌是怎么生成的？数据库里存的是什么？

**表达脉络**：选文件发请求 → 查重复用或新生成 → 随机令牌存摘要 → 24 小时有效期 → 返回链接文本

**要讲到的边界**：为自己的普通文件生成可兑换标识，接收者无需预先成为好友，但仍要登录应用取回。默认有效期为 24 小时。

**追问**

1. 为什么不用自增文件号当链接？
2. 存摘要能保证数据库泄露后链接不可用吗？
3. 为什么不直接用带签名的无状态链接？
4. 一份文件反复点生成会如何？
5. 别人拿到应用内分享链接，是否就能拿到文件？

## 52. 查询已有分享链接并复制

**问法**：为什么还要单独做一个「查询已有链接」的接口？

**表达脉络**：规范路径发请求 → 按所有者查记录 → 服务端时间判状态 → 返回摘要形式链接 → 复制不算分享成功

**要讲到的边界**：让文件所有者重新获得可用的分享文本及其状态，减少重复生成。复制到剪贴板只说明文本已复制，不说明链接当前可兑换。

**追问**

1. 只保存摘要为什么还能重新获取？
2. 复制成功算不算分享成功？
3. 别人能通过文件路径查询我的链接吗？
4. 链接只保存摘要、无法还原原始令牌，有什么替代方案？

## 53. 解析分享链接并取回文件

**问法**：拿到一条分享链接，怎么把文件取回来？

**表达脉络**：提取标识发请求 → 摘要定位记录 → 查生命周期和源 → 取回目录挂条目 → 返回展示名刷新

**要讲到的边界**：把有效链接对应的普通文件安置到当前登录者的云盘。成功结果是创建可见条目，不是浏览器立即下载到本地。

**追问**

1. 为什么不能只检查用户路径上的文件存在？
2. 拿到链接就能匿名下载吗？
3. 链接有效但源被删除呢？
4. 取回后原链接过期，已经取回的文件也消失吗？
5. 凭链接就能取回文件，算不算越权？

## 54. 分享链接状态、续期与重新生成

**问法**：分享链接的有效期、续期和重新生成，分别怎么处理？

**表达脉络**：查状态撤销优先 → 续期保凭据改时间 → 重生成先废旧再建新 → 失败重查询 → 已取内容不收回

**要讲到的边界**：统一判断有效、过期、撤销，支持延长现有链接有效期及更换链接使旧链接失效。当前主要界面入口是续期、重新生成，不能把存在撤销字段等同于已具备独立撤销按钮。

**追问**

1. 续期为什么不换令牌？
2. 过期和撤销为什么不同？
3. 重新生成能保证成功前旧链接一直可用吗？
4. 取回与续期、换链同时发生怎么办？
5. 分享链接到期、续期、重新生成与并发取回怎样测试？

# 底层技术能力（55—58）

> 四项是加分项。要给数字、给代价，不要只讲原理。

## 55. 自研内存池

**问法**：为什么自己写内存池？和 malloc 比解决了什么问题？

**表达脉络**：算大小查来源 → 线程缓存快路径 → 中央页缓存逐层补给 → 释放按页段回流合并 → 收益已实测（微基准 2.3–4.1 倍、驻留更高，不换算整机）

**要讲到的边界**：减少服务端报文频繁申请、释放时的通用分配开销，复用不同尺寸的内存。当前接入点主要是 PDU（协议数据单元）分配，不是已经验证可替换整个进程的任意分配器。

**追问**

1. 为什么不一直用系统分配？
2. 为什么不用每个请求大小一个链表？
3. 三级缓存解决的分别是什么？
4. 完全无锁吗？
5. 一次分配失败怎么办？

## 56. 数据库连接池

**问法**：数据库连接池是怎么实现的？租约什么时候归还？

**表达脉络**：初始化记上限 → 取空闲重开坏连接 → 满则快速失败 → RAII 租约同事务同连接 → 析构自动归还 → 收益已实测（短查询平均耗时降约 87%、吞吐约 7.6 倍，慢查询组持平，不换算整机）

**要讲到的边界**：复用 MySQL 连接、限制连接数量，并让业务在提前返回时自动归还连接。它管理连接借还，不自动解决 SQL 延迟、事务正确性或跨线程亲和性。

**追问**

1. 为什么不用一条全局连接？
2. 为什么池满不等待？
3. 加锁后是不是任意线程都能用？
4. 一个事务中能临时换一条连接继续吗？
5. 为什么用一个全局连接池，而不是每个业务功能各建一个池？
6. 为什么数据库操作放在主线程，而不是丢到子线程执行？
7. 这样长事务不会阻塞主线程的事件循环吗？
8. 性能提升多少，这轮对照是怎么测的？

## 57. 自定义 TCP 二进制协议

**问法**：为什么要自己定二进制协议？TCP 粘包半包怎么处理？

**表达脉络**：填头加正文 → 拆帧循环消费 → 校验长度类型上限 → 鉴权后按号分派 → 编号只追加

**要讲到的边界**：在字节流上恢复报文边界，并承载账号、好友、群、文件和任务控制。它是应用层协议，TCP 本身不保存一次 write（写操作）的消息边界。

**追问**

1. 怎么处理半包、粘包？
2. 攻击者声明超大包怎么办？
3. 所有结构体都能直接跨平台发送吗？
4. 已有编号为何只追加？
5. 调用 connectToHost 会一直等到握手完成吗？

## 58. TLS 加密与服务端证书校验

**问法**：TLS 是怎么接进来的？证书校验做到什么程度？

**表达脉络**：服务端加载证书开监听 → 客户端固定信任 → 握手前禁业务 → 拒错证书不回退明文 → 业务照旧独立鉴权

**要讲到的边界**：为桌面到服务端的连接提供传输机密性、完整性和服务端身份校验。固定信任证书适合受控部署，不能代替密码存储和业务授权。

**追问**

1. 加密了还要检查证书吗？
2. 为什么固定证书而非系统证书机构？
3. 证书验证失败会自动回退明文吗？
4. TLS 1.2是最低版本吗？
5. TLS 握手与持续传输分别有什么开销，怎样比较连接速度、吞吐、处理器占用及失败率？
